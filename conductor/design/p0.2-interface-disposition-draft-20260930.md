# P0.2 E0/C0 interface disposition draft

**Status:** Coordinator proposal for review against the six independent agent
packets. Row dispositions and matrix revisions are not accepted by this draft.

## Six cross-cutting choices

1. **Consumer and keys.** CareOps owns the versioned ED configuration schema and
   its domain keys. Kairos Track 22 may receive a scenario manifest referring to
   that configuration and seeds; it does not own ED clinical key meanings. The
   CareOps ED adapter maps validated keys into approved Kairos Track 03 Flow
   primitives; Track 03 owns execution semantics, not the clinical keys. Kairos
   public API changes still require its own reviewed contract/ADR. E0 validates the
   configuration before scheduling. All numeric leaves in a
   structured value carry a declared unit and frame where spatial; categorical
   coding has a version. No candidate key is frozen until its
   row has a coordinator disposition.
2. **Durations and ticks.** ED configuration represents durations as decimal
   seconds. The proposed initial ED execution profile uses one nanosecond per
   Kairos integer tick, with checked `u128` conversion. The initial C0 panel
   deferred quantum and rounding; its supplemental clock review recommends
   this profile with the conversion details below. Coordinator disposition and
   a deterministic fixture remain required before acceptance.
   Fixed config values must be
   nonnegative and exactly representable at that resolution or validation
   fails; trailing decimal zeroes beyond nine places remain valid when exact.
   Parse decimal values exactly before checked scaling; reject non-finite values,
   negative values and overflow. Do not use binary
   floating point to order events. For sampled nonnegative durations, propose
   deterministic ceiling to the next tick at the model boundary using either
   an exact rational sample or the exact represented value of a versioned finite
   sampler output. Reject non-finite and negative draws; zero remains zero, and
   each draw's upward error is less than one nanosecond. This positive bias may
   accumulate across draws; record the sampler version,
   conversion method, rounded-draw count and input precision in the run manifest.
   The exact sampled-draw implementation needs a Q/C phase fixture. No floating value participates in event
   ordering. A different tick quantum requires an explicit versioned profile
   and compatibility review, not an unlabelled runtime switch.
3. **Absolute schedules.** Relative synthetic schedules start at tick zero.
   Each normalized dataset/run artifact declares one UTC origin; timestamped
   traces require an explicit origin, source IANA zone or fixed offset, original
   timestamp text/value and precision. Recurrent local schedules require an
   IANA zone and an explicit fold/gap policy. The current reference fixture
   accepts relative schedules or explicit-offset timestamps and rejects naive
   local timestamps; local recurrence support stays disabled until a tested
   adapter and declared gap-shift policy exist. The generic MVP fixture uses
   relative schedules. Normalize to UTC before checked
   subtraction to ticks. Reject pre-origin, ambiguous folds without an explicit
   offset/fold, nonexistent local times without a declared shift policy, unknown
   zones, overflow and sub-nanosecond values. Retain original source precision:
   normalized nanosecond ticks do not imply nanosecond-observed timestamps.
   Preserve occurrence/recorded/message timestamp lineage and recording delay
   separately; recorded/message time never substitutes
   for occurrence time. The generic profile can use relative schedules without
   inventing a calendar origin.
4. **Spatial measures.** Distances are metres and speeds metres/second;
   modelled route duration uses distance divided by speed and ceiling to ticks.
   Named locations/zones, resource/staff bindings and eligibility are ordinary
   minimum model inputs even when Micro movement is disabled. Route graphs,
   lengths, speeds and travel costs are optional Micro Mode inputs. Detailed
   CAD/geometry and visualization remain later work.
   A declared deterministic or shortest route suffices until route-choice
   behavior is explicitly enabled; no route-choice distribution is inferred.
   A spatial parameter is generative unless an explicit observed measurement
   mapping makes it a calibration target.
5. **Probability and observation boundaries.** Every probability table declares
   its conditioning variables, denominator, applicability, normalization rule
   and unknown-category handling. Aggregate marginal counts do not establish
   patient-level joint distributions. Generative scenario inputs, observed EHR
   fields and calibration targets have separate records and provenance. Do not
   sample an elapsed interval that already includes separately simulated queue,
   work or transit time. Admission disposition is generated once for the ED
   cohort. `admissiondemand` denotes ED-generated requests or a mutually
   exclusive external competing-demand fixture, never a second patient-arrival
   stream. Inpatient bed offers are finite, destination-compatible and may have
   lifetime/withdrawal and competing demand. Boarding elapsed time emerges
   from the admission decision through offer, acceptance, transport and actual
   ED departure while the ED resource remains occupied; the observed target
   declares cohort, start/end anchors, event mapping and censoring. It is a target
   unless an explicit residual boundary delay is modeled. Disposition work
   duration excludes this boarding/transfer interval.
6. **Stages.** E0's one-patient skeleton uses a narrow deterministic fixture.
   The E2 functional MVP configuration additionally needs arrivals, acuity,
   triage/assessment/diagnostic/treatment/disposition and boarding pathways,
   physical/open/staffed treatment-space capacity, staff skills/shifts, equipment,
   zones, cleaning/reservations, a finite admission boundary, horizon and a
   **single run seed**. Staff counts distinguish employed, rostered, present and
   task-eligible staff; absence and overtime change time-varying capacity. It
   must support waiting, length-of-stay, throughput,
   occupancy/utilization and terminal/unfinished counts. The current
   `ed.experimentcontrols.seedstreams` row must expose the run seed at MVP stage;
   named multi-stream derivation remains a Kairos Track 01 contract. Optional
   Micro route inputs are enabled only for an explicit Micro Mode scenario.
   Fatigue, learning, companions and
   detailed physiology remain deferred unless later evidence and scope require
   them. Multi-person composite tasks have an explicit supported or unsupported
   status under E2.2. A deferred row needed by the MVP blocks that profile rather than
   silently receiving a default.

E0 validation must distinguish unknown capacity from zero and enforce applicable
cross-field limits such as staffed <= open <= physical, resource/zone references,
and route endpoints when a route graph is enabled. The current schema validator
only proves structural coverage; these cross-field checks require implementation
and negative fixtures before P0.2 closes.

## Row-level review rule

Each of the 101 rows needs E0 and C0 role recommendations, a coordinator
decision, and a recorded reason for any disagreement. `not_applicable` applies
only to an explicitly disabled stage or mode, not to unknown evidence. A
`revise` decision must name the replacement consumer, key, unit or stage/use.
The matrix and response CSV remain proposed until every MVP-relevant row is
resolved, schema/validator tests pass, and the manual patient/staff walkthrough
finds no consumed input without an ID.
