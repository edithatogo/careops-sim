# P0.2 structured matrix revision contract

**Status:** coordinator drafting contract; output chunks require integration review.

The 101 stable `parameter_id` values and their source order in
`parameter-ids.json` are fixed for this revision. The existing usage matrix and
E0/C0 response CSV are input evidence, not approved runtime configuration.
Create three disjoint JSON chunks for data rows 1–34, 35–68 and 69–101. The
coordinator joins them after reviewing each row and the cross-cutting decisions.

Each chunk has `schema_version: 1`, `status: "draft_for_coordinator_review"`,
`first_row`, `last_row`, and `entries`. Each entry has:

- `row` (one-based data row), `parameter_id`, `family` and `decision` (`accept`,
  `revise` or `defer`). `decision` comes from the provisional CSV unless the
  coordinator's row-review reconciliation explicitly changes it; name any
  difference in `review_note`.
- `config_key`, `consumer`, `unit_class`, `unit_contract`, `profile_stage`,
  `profile_use` and `value_role`. These are the **resolved proposal**, not a
  copy of a superseded field when the replacement changes it. `value_role` is
  `generative`, `observed_target`, `source_metadata`, `control`, `mixed` or
  `deferred`; explain a `mixed` row in `profile_use`.
- `resolution`: one concise paragraph that preserves the E0/C0 boundary and
  explicitly names any conditional applicability or deferral trigger.
- `open_gate`: an array of specific implementation/evidence checks still needed
  to use the row in an E2 profile; use an empty array when none is identified.
  A deferred row names its re-entry trigger in `resolution` and cannot silently
  appear in an MVP profile.

Do not invent empirical numbers, clinical values, distribution families,
default profiles or runtime pass claims. `MVP_minimum` means the generic E2
profile must supply or derive the field; `MVP_conditional` means required only
when the named pathway/mode is enabled; `hardened_v1` and
`deferred_or_post_v1` are excluded from E2 unless a later reviewed change says
otherwise. `E0_fixture` denotes the narrower deterministic skeleton.

The coordinator must independently compare the joined rows to the registry,
E0/C0 votes and replacement texts. In particular, row 35 is optional
route-specific active disposition work, row 36 is an observed boarding boundary
unless a separately identified residual is modeled, row 37 separates Macro and
Micro travel, row 62 means graph-edge metres rather than drawing scale, row 63
named location/zone IDs are MVP minimum, row 75 is external competing admission
demand, row 89 includes one MVP run seed, and row 90 is field-level units plus
the scoped ADR-0004 clock profile. None of those contracts is implemented merely
by listing it here.
