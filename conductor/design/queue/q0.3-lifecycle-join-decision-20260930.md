# Q0.3 lifecycle causal join decision

**Status:** Coordinator design disposition for Q0.3 review. This freezes the
intended contract for the single-resource FlowRuntime design; it does not claim
an implemented Arrow stream, exact public API approval, or portable checkpoint.

## Command and event causality

Every public Flow command that can change resource state enters the private
buffer. Admission, cancel, reprioritize, capacity change and explicit release
are applied only while handling an internally scheduled Flow command-dispatch
event. Its dispatched `EventId` is the causal ID of all state transitions
committed by that command, including queue draining it triggers. Work completion
and waiting-deadline handlers use their own dispatched event IDs when they commit
the transition. If an earlier Flow dispatch materializes a due completion or
deadline at the same tick during its boundary phase, that transition uses the
currently handled event's ID; the later stale token emits no second row. A notification
callback that submits another command schedules a later command-dispatch event;
the callback's notification event does not become that command's causal ID. This retains
one scheduler clock and makes every lifecycle row joinable to an actual
`event_log.v1` dispatched row. A caller-supplied event kind in the reserved
4000–4003 range is rejected at all public ingress points, including handlers
and adapters. Internal scheduling alone may use those codes.

Command admission is not resource-state commitment. A rejected or stale command
has no transition for its explicit operation, although the dispatch may first
materialize independent due boundary transitions. A cancelled scheduler event has no lifecycle row;
a dispatched cancellation command may commit a `cancelled` request transition.
Continuation delivery is an observation, not another resource transition.

## Lifecycle identity and ordering

The v1 work item requests one unit from one resource; multi-resource and partial
request transitions are outside this contract. Every v1 lifecycle row has a
required `resource_id` and required generational `request_id`. `owner_id` and
`work_id` may be null where no such entity applies. Its stable request handle
is the lifecycle subject, so terminal uniqueness is per `(run_id, request_id)`.
The terminal tokens are `completed`, `released`, `timed_out`, `cancelled` and
`aborted`; exactly one may be committed for a request. `preempted` is
nonterminal. A later grant of suspended work emits `resumed`; a later grant of
restart-policy work emits `restarted`. Neither also emits `granted` for that
same allocation; `granted` denotes a first grant. Strategy and reason tokens
are versioned with the lifecycle vocabulary, not free-form clinical labels.
Completion must not also emit `released` for the same outcome.

The sidecar key `(run_id, causal_event_id, transition_ordinal)` is unique and
joins exactly one `event_log.v1` row whose status is `dispatched`.
Ordinals start at zero and are contiguous in committed transition order within
each dispatch. Resource and queue traversal is canonical before ordinals are
assigned. Assigning beyond the proposed `UInt32` ordinal range is a checked
error, never wrapping. Within a dispatch, expire affected deadlines in
`PriorityKey` order, complete due timed work by `(completion_at, request ID)`,
apply the explicit operation, then arbitrate affected resources in resource-ID
order, as in the Q0.2 boundary contract. Across dispatches, core `(time, priority,
sequence)` ordering remains authoritative. A dispatch with no committed
resource transition has no sidecar row. A delivered notification refers back
to its originating `(run_id, causal_event_id, transition_ordinal)` and never
creates another lifecycle row merely by being delivered.

The proposed sidecar uses the existing event-log 12-byte generational event-ID
and 16-byte little-endian tick encodings, with `time_scale = ticks`. Optional
fields are null only when the transition does not define them; zero is a real
value, not a missing marker. The Q4 schema review must publish a token-to-field
applicability matrix, including post-commit counts/capacity, lease revision and
reason. Track 04 owns the final Arrow schema and roundtrip
implementation. The current `event_log.v1` schema and `custom:<code>` encoding
remain unchanged.
