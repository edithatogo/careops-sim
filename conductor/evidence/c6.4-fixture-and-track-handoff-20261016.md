# C6.4 Task Evidence: Fixture and Contract Handoff to Metal, PDES, and Distributed Tracks with Visualization Snapshot and Wasm Parity Requirements

## Objective

Hand off fixtures and contracts to existing Metal/PDES/distributed tracks. Add future visualization snapshot/Wasm parity requirements from [hybrid-model appraisal](../hybrid-model-insights.md); render-rate changes must not change simulation results. Hardware/UI work stays with those owners.

## Implementation Details & Handoff Contracts

### 1. Metal & GPU Compute Acceleration Handoff (Kairos Track 32: `kairo-ecs-gpu`)

Qualified in `libs/kairos/crates/kairo-ecs-calibration/tests/c64_handoff_contracts.rs`:
- **Offloaded Calibration Kernels**:
  - Distance metrics calculations for Wasserstein-1 ($W_1$) and Kolmogorov-Smirnov ($KS\ D$) across candidate evaluations can be offloaded to WGSL compute shaders targeting Metal on Apple Silicon macOS (`wgpu-backend`) and CUDA on Linux.
  - Contract specifies `#[repr(C)]` memory layouts (`AgentParticle`, `DesEvent`) for zero-copy host-to-device transfers.
- **Canonical Reduction & Tolerance**:
  - To prevent floating-point reduction non-associativity drift between GPU parallel trees and CPU sequential loops, input samples are sorted in canonical ascending order prior to reduction.
  - Declared numerical tolerance: $\epsilon \le 10^{-12}$. Any accelerated GPU shader reduction must reproduce the CPU reference distance within this bound.
- **Hardware Isolation & Non-Configured Fallback**:
  - In environments without active GPU hardware (headless CI, containerized workers), the engine guarantees 100% clean fallback to `CpuFallbackCompute`.
  - Non-configured backends return explicit typed contract errors (`WGPU_BACKEND_NOT_CONFIGURED`, `CUDA_BACKEND_NOT_CONFIGURED`) rather than crashing, panicking, or silently corrupting evaluations.

### 2. PDES Parallel Execution Handoff (Kairos Track 34: `kairo-ecs-pdes`)

Qualified in `libs/kairos/crates/kairo-ecs-calibration/tests/c64_handoff_contracts.rs` and `crates/careops-ed/tests/c64_handoff_contracts.rs`:
- **Logical Process (LP) Candidate Partitioning**:
  - Multi-candidate calibration sweeps and disjoint spatial pods/zones are partitioned across `LogicalProcess` (LP) instances identified by `LpId`.
  - Inter-LP events (patient handoffs between triage, acute bays, subacute zones, and diagnostics) map directly to `RemoteEvent` structures.
- **Chandy-Misra-Bryant (CMB) Lookahead & Null-Message Protocol**:
  - Conservative PDES deadlock avoidance requires strictly positive lookahead ($\text{lookahead} > 0$).
  - Minimum edge transit durations in the deterministic `TransitModel` graph ($\ge 1$ tick) and positive clinical work durations guarantee positive lookahead for all LP boundaries.
- **Worker Completion Order Invariance (C-06 Gate)**:
  - Irrespective of physical thread scheduling, network jitter, or completion message arrival order across LPs, the candidate ranking table, objective scores, and winner selection (`winner == "c000004"`) are bit-for-bit invariant.

### 3. Distributed Simulation Handoff (Kairos Track 35: `kairo-ecs-mpi` / `kairo-ecs-grpc`)

Qualified in `libs/kairos/crates/kairo-ecs-calibration/tests/c64_handoff_contracts.rs` and `crates/careops-ed/tests/c64_handoff_contracts.rs`:
- **Arrow Telemetry Batch Transport**:
  - High-throughput telemetry and residuals generated during distributed simulation are packed into `MpiTelemetryBatch` and `GrpcTelemetryBatch` envelopes carrying Arrow IPC byte payloads (`arrow_ipc_payload: Vec<u8>`).
  - Standardized schemas (`calibration_residual.v1`, `calibration_metric.v1`, `careops.ed.spatial_transit.v1`) ensure zero-copy deserialization on the aggregation coordinator.
- **Distributed Reduction & GVT Advancement**:
  - Global Virtual Time (GVT) advances deterministically across cluster nodes using `all_reduce_min` over local next-event timestamps and transit envelopes in flight.
- **Protocol Emulation & Fault Isolation**:
  - Protocol emulators (`PdesTransport`) verify distributed message round-trips, heartbeat monitoring (`WorkerHeartbeat`, `WorkerStatus`), and node partition handling in pure software without requiring physical MPI/gRPC clusters.

### 4. Visualization Snapshot & Wasm Parity Requirements (`hybrid-model-insights.md`)

Qualified in `libs/kairos/crates/kairo-ecs-calibration/tests/c64_handoff_contracts.rs` and `crates/careops-ed/tests/c64_handoff_contracts.rs`:
- **Decoupled Render Loop & Zero Simulation Interference**:
  - The simulation engine (Kairos DES/ABM) is the sole authoritative owner of virtual simulation time (`SimTime`), state transitions, and discrete event queues.
  - Visual renderers (PixiJS / WebGPU / Canvas) operate on an independent wall-clock display ticker (`requestAnimationFrame`). The render loop NEVER advances or controls simulation ticks.
  - Render callbacks NEVER mutate ECS components or simulation state directly. Visual interactions are submitted via timestamped command buffers.
- **Render Rate Invariance (0 FPS, 30 FPS, 60 FPS, Variable Frame Drops)**:
  - Rigorously proven by test suites: executing a simulation headless (0 FPS), with 30 FPS snapshot extraction, with 60 FPS snapshot extraction, or under heavy frame-dropping jitter produces **100% bit-for-bit identical** patient outcomes, event logs, summary metrics, and serialized SHA-256 output hashes.
  - Display interpolation between snapshots is strictly cosmetic and has zero effect on model trajectory or random number sequences.
- **Wasm Safe Integer Tick Bounds**:
  - Core simulation ticks are represented by 64-bit and 128-bit unsigned integers.
  - In JavaScript/Wasm environments, integer arithmetic is bounded by the IEEE 754 safe integer limit (`MAX_SAFE_INTEGER = 2^53 - 1 = 9,007,199,254,740,991`, `MAX_EXACT_TICK`).
  - Serialization to TypeScript/Wasm interfaces preserves tick precision via `BigInt` and 16-byte little-endian hex representations (`timeTicksLeHex`), preventing silent float truncation.
- **Slow Consumer Bounded Buffer & Backpressure**:
  - Live snapshot streams to visual frontends enforce a bounded queue capacity ($K = 64$ frames).
  - Under client rendering delay or UI lag, older intermediate display snapshots are coalesced or dropped.
  - The simulation engine is NEVER blocked or stalled by visual rendering backpressure, and the underlying event logs and Arrow export tables remain 100% lossless and complete.
