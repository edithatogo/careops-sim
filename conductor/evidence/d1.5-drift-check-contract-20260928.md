# D1.5 dispatch and acceptance drift-check contract

Status: coordinator-frozen interface for `D1.5.drift`; independent review is
required before worker dispatch. This builds on the accepted
[receipt validator](d1.5-receipt-validator-implementation-20260928.md) and the
[D1.5 receipt contract](d1.5-command-attempt-receipt-contract-20260928.md).

## Interface

Add `tools/receipt_drift.py` with
`verify_acceptance(receipt, receipt_path, packet, repo_root) -> list[str]` and CLI:

```text
python3 tools/receipt_drift.py verify RECEIPT_JSON PACKET_JSON --repo ROOT
```

`repo_root` is the parent checkout root. Resolve `packet.target_repo` beneath
it for Git HEAD, input files and output files; resolve `source_hashes` and
prerequisite artifact paths from `repo_root`, matching `mvp.prepare`. The CLI is
read-only. It returns exit 0 and a short success message only when all
acceptance checks pass; otherwise it returns exit 1 and sanitized error
messages. It must not print input values, arbitrary paths or receipt payloads.
Use the accepted `command_receipts.validate_receipt` function for the receipt's
schema and receipt-internal semantic checks. Use only the Python standard
library. Reject malformed packet shapes, unknown statuses, noncanonical paths
and unsafe types without raising or echoing untrusted values.

`receipt_path` is canonical and parent-root-relative. It must equal the
coordinator-bound `packet.coordinator_binding.receipt_path`. The CLI reads and
validates the packet first, checks this path and its containment, then loads the
receipt; it must not open an arbitrary receipt path first.
This D1.5 leaf is parent-tooling work, so its packet must set `target_repo` to
`.` and reserve both `receipt_path` and `result_path` in `write_paths`.

## Checks

At dispatch, the coordinator continues to run
`python3 tools/tasks.py packet-check PACKET_JSON`; this binds current Git HEAD,
packet input/context hashes, source/skill hashes and packet structure before a
worker starts. Tests for this leaf must verify that base, input and source/skill
drift cause this dispatch check to fail.

At acceptance, `verify_acceptance` is a pre-commit check on the worker's target
checkout. The worker returns a diff for review and must not advance that
checkout's HEAD; the coordinator commits only after this check passes. The
verifier is not intended to validate an already integrated commit. It must:

1. Require a valid worker receipt with `status=ready_for_review`, then match its
   `packet_id`, `target_repo`, `base_commit` and complete `inputs_sha256` map to
   the supplied prepared packet.
2. Recheck current Git HEAD against the packet base. Recompute every packet
   `input_hashes` path in the target checkout and every `source_hashes` path in
   the parent checkout. This includes bound context, recipe, worker instructions
   and any skill source included in the packet. Fail closed on missing files,
   invalid paths or hash drift.
3. Match the receipt command list one-for-one and in order with the packet's
   `verification` list on `argv`, `cwd` and `expected_exit`; reject missing,
   extra or altered verification commands.
4. Read the coordinator-authored
   `packet.coordinator_binding.required_outputs` list. Require a nonempty,
   unique list of canonical repository-relative paths, each within `write_paths`
   and disjoint from packet inputs. Require every listed path in
   `receipt.outputs_sha256`. Define an extraneous output as a `changed_paths` or
   output-hash path outside `write_paths`; optional outputs inside a write
   reservation are allowed and still hash-checked. Require receipt
   `changed_paths` to exactly match the target checkout's actual Git changed
   paths. Actual changes include staged, unstaged and untracked files from
   NUL-delimited Git status output. Parse names without Git quoting; reject
   rename/copy and deletion states. Exclude exactly `result_path` and the
   bound `receipt_path` before comparing. Recompute each declared output hash
   from its file in the target checkout.
5. Exclude the receipt JSON and packet `result_path` from `required_outputs`,
   `outputs_sha256` and `changed_paths`; these control/evidence artifacts cannot
   self-hash. The receipt is a packet write reservation in this leaf. The
   coordinator records its hash outside the worker receipt.
6. Require `packet.coordinator_binding.prerequisite_receipts` to cover exactly
   `leaf_dependencies`. For each prerequisite, recheck `status=accepted`, a
   nonempty reviewer, `all_instances_accepted=true`, nonempty unique
   `expected_instances` and `accepted_instances` lists of nonempty strings that
   are exactly equal, and a nonempty artifact map with canonical paths and
   SHA-256 values. Recompute every prerequisite artifact path/hash from
   `repo_root`; stop on missing or changed evidence.
7. Resolve paths inside their repository roots, reject symlinks that escape,
   and reject output paths that resolve into a protected path or alias an input.
   Do not modify packets, receipts, files, task status or Git state.

The packet's `required_outputs` is a coordinator binding, not a worker-selected
list. For this leaf, it names the code and test outputs; it excludes the packet
`result_path` and coordinator-bound receipt sidecar. The verifier rechecks the
explicit coordinator prerequisite assertion but does not independently discover
missing instances beyond comparing the exact expected/accepted lists. It assumes
the coordinator supplied the intended packet and does not authenticate packet
authorship, worker identity or command execution. It does not provide an atomic
writer lease, checkpoint recovery, or hidden-oracle isolation; those remain
D1.5.recovery and D1.5.ownership work.

## Acceptance cases

Unit/integration tests must cover a valid pre-commit acceptance and reject:
changed live base, changed packet input, changed source/skill input,
receipt/packet identity or input-map mismatch, missing required outputs,
changed/extraneous output paths, altered command argv/cwd/exit, output hash
mismatch, changed prerequisite artifact, empty/incomplete/mismatched instance
sets, unsafe/traversing path, protected-path alias, receipt-path mismatch and a
symlink that escapes the repository. Git changed-path checks include staged,
unstaged and untracked files and reject deletions. Dispatch tests must show
`tasks.packet_errors` rejects stale base, input and source hashes. Use temporary
local Git repositories and synthetic non-sensitive fixtures only; never contact
a remote or alter a real worktree during the tests.
