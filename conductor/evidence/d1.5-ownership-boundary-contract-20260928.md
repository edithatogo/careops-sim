## Reservation behavior in scope

`tools/tasks.py select(..., active_paths=...)` is a deterministic planner. It
omits ready tasks whose declared write reservations overlap an active path by
equality or ancestry. The coordinator is the sole owner of the run ledger and
must pass all live reservations to the planner before dispatch. The existing
`test_active_reservations_block_selection` fixture is the behavioral oracle;
add coverage for both an ancestor and a descendant overlap if the current
fixture does not demonstrate them.

This proves planner rejection only when the coordinator supplies the active
paths. It does not provide atomic reservation acquisition, protect against two
independent coordinators, or prove writer termination on timeout. The current
execution protocol intentionally has one coordinator and is not a distributed
lease service.

## Evaluation boundary

The local worker/subagent shares this host and filesystem. There is no
repository-level access-control boundary that prevents it from reading a
file merely because that file is omitted from packet context. Therefore this
leaf must not claim technical hidden-oracle isolation. No oracle answers,
protected fixtures, or secrets may be included in a worker packet or receipt.
The current pilot remains supervised and non-hidden; skill promotion remains
off.

Before running any untrusted or held-out evaluation, D2's local CI/security
fixtures must exercise the actual execution boundary: untrusted work must not
read coordinator-held oracle material or obtain secrets, and a negative access
probe must fail closed. If the local runner cannot demonstrate this, keep
hidden evaluation disabled until a supported isolated environment is available.
