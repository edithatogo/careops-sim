# D1.5 receipt validator implementation

Status: `D1.5.receipts.schema-validator` accepted by the coordinator at commit
`d676b8a142ecc911627639b080e38f3082123e18`. The D1.5 parent remains in progress.

## Scope and review

The implementation adds a standard-library-only validator for the frozen
metadata-only receipt schema and a CLI:

```text
python3 tools/command_receipts.py validate PATH
```

It checks schema constraints, canonical paths, UTC chronology including
sub-microsecond fractions, nonoverlapping command intervals, receipt-internal
`ready_for_review` consistency, and common credential/private-data patterns.
Diagnostics do not echo receipt values or arbitrary property names. Pattern
checks are conservative and cannot certify arbitrary free text as safe.

Attempt 1 stopped before source edits when the worker found that receipt-only
validation could not determine packet-specific required outputs. The coordinator
clarified the contract so standalone validation checks receipt-internal output
coverage while packet-specific completeness and hash recomputation remain
coordinator acceptance checks. A separate read-only review approved that
clarification at `d9aa7e258134d6591aadb3800b12664f9302c497`. Attempt 1's packet,
context and blocked result remain archived in the local run ledger.

Attempt 2 was independently reviewed. Review findings on sensitive mapping keys,
split credential flags, diagnostic redaction, timestamp precision and JSON
numeric parity were resolved and regression-tested. The final reviewer found no
remaining blocker. The accepted source and test files are
[command_receipts.py](../../tools/command_receipts.py) and
[test_command_receipts.py](../../tests/test_command_receipts.py).
