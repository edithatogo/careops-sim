# D1.5 interrupted-attempt recovery contract

Status: coordinator-frozen interface for the `D1.5.recovery` fixture and
decision helper, independently reviewed with no remaining contract blocker.
This is supervised coordinator tooling, not an unattended process supervisor
or writer lease.

## Interface and ownership

Add standard-library-only `tools/recovery.py` with:

```text
inspect_attempt(ledger, packet, checkpoint, packet_sha256, repo_root, *,
                worker_stopped_attestation=None, new_attempt_id=None,
                prior_attempt_ids=(), issue_resolution=None)
    -> dict[str, object]
```

The function is pure: it reports a recovery decision and never runs a command,
changes a packet, edits an earlier attempt, writes a checkpoint, reserves paths
or dispatches a worker. The coordinator remains the only writer of run ledgers
and must persist any returned retry plan as a new immutable attempt record. A
retry uses a new `attempt_id` and `supersedes_attempt_id`, and reuses the exact
same prepared packet bytes/base/input hashes. The supplied `packet_sha256` must
match the run ledger's `packet_sha256`; otherwise return `rebind_required` with
no retry plan. Changed base, input/source hashes, or packet scope require the
coordinator to re-prepare and review a packet. A same-scope rebind keeps the
packet ID but creates a new packet revision/hash; a scope/interface/objective
change gets a new packet ID and `supersedes_packet_id`. Those rebind workflows
remain coordinator work outside this helper. Preserve the old packet bytes and
hash in prior attempt lineage. Never overwrite the prior attempt's receipt,
result, packet, or checkpoint.

`tools/recovery.py inspect LEDGER_JSON PACKET_JSON CHECKPOINT_JSON --repo ROOT`
may emit the same sanitized decision as JSON. It reads inputs only, does not
print arbitrary paths or payloads, and exits nonzero for malformed input or an
unsafe/blocked decision. It does not create a retry attempt.

The coordinator checkpoint is a versioned JSON object:

```json
{
  "schema_version": 1,
  "packet_id": "packet-id",
  "attempt_id": "attempt-id",
  "steps": [
    {"index": 0, "label": "exact packet step", "state": "accepted",
     "artifacts_sha256": {"relative/output": "<sha256>"}},
    {"index": 1, "label": "exact packet step", "state": "not_started",
     "artifacts_sha256": {}}
  ]
}
```

Step labels and order must exactly match `packet.steps`. Allowed states are
`accepted`, `started_unknown`, and `not_started`. An `accepted` step has a
nonempty map of canonical repository-relative artifact paths and SHA-256
digests, each rehashed from the target checkout. `started_unknown` means the
action may have produced external or local side effects without coordinator
acceptance; it blocks automatic retry until a human reconciles that action.
The accepted prefix must be contiguous; an unknown or not-started step cannot
be followed by an accepted step. Create the initial checkpoint before dispatch
with every packet step set to `not_started`. The checkpoint must bind to the
exact prior packet and attempt IDs in the run ledger. Each accepted artifact
must be within a packet `write_paths` reservation and must not resolve to or
overlap a packet input, protected path, `result_path`, or coordinator-bound
receipt path.

## Recovery rules

The decision rechecks packet readiness against the current checkout using the
existing packet validation path, including its base and input/source hashes,
and enforces repository-root containment for every path. If the packet is
stale or its hash differs from the run ledger, return `rebind_required` with no
retry plan; never reuse it. Rehash every accepted checkpoint artifact
and reject path traversal, symlink escape, changed artifacts, duplicate step
indices, unknown states, malformed ledgers, mismatched packet/attempt IDs, or a
new attempt ID that is empty, equal to the prior ID, or present in the supplied
`prior_attempt_ids` set. The coordinator supplies this set from the relevant
run-ledger directory; the helper does not infer a global task registry.

Run-ledger status rules:

| Prior status | Recovery decision |
| --- | --- |
| `prepared` | Dispatch that exact attempt only after packet revalidation; no retry needed. |
| `running` | Treat as `suspected_stale`, never infer death from elapsed time. Require a coordinator stop attestation before any retry plan. |
| `ready_for_review` | Route to receipt/diff acceptance; do not dispatch another writer. |
| `blocked`, `failed`, `cancelled` | A new attempt may be proposed only with both a bound stop attestation and a bound issue-resolution assertion. |
| `integrated` | Terminal; reject retry. |

The stop attestation is coordinator-authored input bound to the exact
`packet_id` and `attempt_id`, with a nonempty confirmer, UTC timestamp, and
basis. For `blocked`, `failed`, or `cancelled`, also require a coordinator issue
resolution bound to those IDs, with a nonempty resolver, UTC timestamp, and
sanitized resolution summary. These inputs gate a recommendation; the helper
does not authenticate them. They record operational observations; they do not
cryptographically or technically prove that a process has stopped. Worker
heartbeats and worker-reported receipts/checkpoints are evidence to inspect, not
authority to accept side effects.

For an eligible retry, report the exact ordered accepted-step prefix and its
verified artifact hashes, the first `not_started` step as `resume_step`, and a
new linked attempt identity. Skip accepted steps only when every declared
artifact still hashes correctly. If any step is `started_unknown`, return a
manual-reconciliation blocker and no retry plan; never assume that repeating
the step is safe. This leaf does not automate reconciliation of uncertain
external side effects; the coordinator must resolve and re-prepare separately.
If every step is accepted, return review/integration rather than proposing an
empty retry.

## Acceptance tests

Use temporary local Git repositories and synthetic data only. Cover:

- a killed-worker fixture where a coordinator-confirmed stopped attempt resumes
  at the exact first unaccepted step and preserves prior artifacts;
- accepted side effects are skipped only after artifact rehash, while a changed
  or missing artifact blocks recovery;
- unconfirmed `running`, `started_unknown`, stale base/input/source hashes,
  `ready_for_review`, and `integrated` each produce their specified non-retry
  decision;
- blocked/failed/cancelled retries require bound stop and issue-resolution
  assertions, plus a fresh attempt ID linked to the prior attempt;
- mismatched checkpoint/packet/attempt IDs, duplicate or out-of-order steps,
  unknown status/state, malformed types, traversal and symlink escapes fail
  closed with sanitized diagnostics;
- accepted checkpoint artifacts outside `write_paths`, or resolving into an
  input, protected path, result or receipt sidecar are rejected;
- no function or CLI path executes commands or modifies a prior attempt.

The MVP packet will own only `tools/recovery.py`, `tests/test_recovery.py`, and
its result/receipt sidecars. Required commands are the focused test module, the
full local unittest suite, and `git diff --check`.

## Limits

This fixture tests coordinator decisions against synthetic checkpoints. It does
not kill/restart a real process, prove external side effects are exactly once,
authenticate coordinator attestations, provide an atomic multi-coordinator
lease, or isolate hidden evaluation inputs. The separate D1.5.ownership leaf
owns conflicting-writer rejection and evaluation-boundary evidence. Those
limits must remain visible in status and downstream readiness claims. The
helper returns a retry record; the coordinator must persist it without
clobbering any existing attempt record. The helper does not implement or prove
that no-clobber operation or a multi-coordinator lease.
