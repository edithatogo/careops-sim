## Completion-state guard

run_scenario constructs one private scheduler and schedules one arrival for each
patient index. Arrival handling inserts that index into the resource waiting
queue once. start_waiting rejects an index that already has start_tick, sets
start_tick before scheduling completion, and creates at most one completion
token for that index. Horizon truncation may create no completion token.
No public interface injects, duplicates or reschedules these private events.
Therefore each reachable completion has completion_tick None and start_tick
Some. Both operands of the rejection condition are false, for both `||` and
`&&`. The mutant is equivalent within this closed public scheduling invariant.
Corrupted or externally injected tokens could distinguish them; this is not a
claim that such fault injection was tested or is supported. Retain the defensive
original guard and reassess if event ingress/rescheduling becomes public.

## Count-conservation guard

arrivals is results.len(). completed and started count subsets of that same
results vector, so each is at most arrivals. unfinished is arrivals - completed.
The subtraction cannot underflow, and completed + unfinished equals arrivals
without overflow because that sum is exactly the existing vector length.
Consequently completed + unfinished != arrivals and started > arrivals are both
false for every reachable constructed result. Replacing `||` by `&&` cannot
change public behavior under these invariants. The guard stays in production.
Reassess if summary counts acquire independent sources or partial result joins.
