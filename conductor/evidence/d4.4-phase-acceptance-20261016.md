## 2. Formal Exit Criteria Readback

The plan specification for Phase D4 defines the exit condition:
> **Exit:** verifiable release candidate evidence, no unresolved critical release risks.  
> **Manual verification:** independent install and attestation/checksum verification.

### 2.1 Verification Evidence
1. **Verifiable Release Candidate Evidence**:
   - Every distribution archive (`careops-ed-0.1.0.tar.gz`, crates, CLI binaries) is cryptographically bound to its unique SHA-256 digest.
   - The SPDX 2.3 SBOM explicitly models all runtime packages, component files, verification codes, and `Apache-2.0` license assertions.
   - The in-toto SLSA v1 Provenance attestation records builder identity, resolved commit dependencies, and invocation parameters.
   - All release metadata and attestation documents are verified to be within the 30-day freshness horizon.

2. **No Unresolved Critical Release Risks**:
   - Memory safety is enforced by architectural isolation: safe Rust domain code forbids unsafe blocks, while foreign pointers are quarantined in dedicated FFI crates.
   - Concurrency is restricted to deterministic message passing without mutable shared state, eliminating race conditions.
   - All six mandatory failure gates fail closed upon encountering uncommitted files, missing archives, corrupted bytes, expired evidence, wrong commits, or incompatible schemas.
   - Autonomous publication commands are hard-blocked by [`tools/rollback_rehearsal.py`](../../tools/rollback_rehearsal.py), requiring explicit human maintainer authority (`CAREOPS_HUMAN_MAINTAINER_AUTHORITY=1`).

3. **Manual Verification Receipt**:
   - An independent installation and verification drill was executed using [`tools/release_rehearsal.py`](../../tools/release_rehearsal.py):
     ```bash
     # Step 1: Package clean release into an external directory
     python3 tools/release_rehearsal.py package --output-dir /tmp/careops-release-test
     
     # Step 2: Verify downloaded bundle as an independent consumer (no repo access)
     python3 tools/release_rehearsal.py verify --dist-dir /tmp/careops-release-test
     ```
   - *Receipt Outcome*: Verified `careops-ed-0.1.0.tar.gz` bit-for-bit against `SHA256SUMS`, confirmed SPDX 2.3 component checks, validated SLSA v1 commit claims against HEAD (`c656f04a0f03a42f681bdc44ccc39269d183a333`), confirmed evidence age of 0 days ($\le 30$ days), and validated license compliance across all seven upstream owners.
