## 2. Formal Exit Criteria Readback & Manual Verification Drill

The plan specification for Phase D5 defines the exit condition:
> **Exit:** demonstrated maintenance loop with bounded cost and correct failures.  
> **Manual verification:** pause and resume a job without duplicate edits or publication.

### 2.1 Bounded Cost and Correct Failures Verification
1. **Bounded Cost**:
   - Maintenance routines run on strict 60-second timeouts and 3-attempt retry ceilings.
   - Computational burden is minimized by 0-change silence (average silent execution duration: 183.47 ms).
   - Agent evaluation across 6 held-out benchmark tasks logged a total operational cost of $0.2030 (average $0.0338/task) with 0 human interventions required for routine tasks.
   - Automation ROI framework enforces $AER \ge 2.0$, ensuring maintenance automation saves significantly more maintainer effort (12.0 hours saved vs 1.0 hour triage, $AER = 8.0$) than it consumes.
2. **Correct Failures**:
   - Negative failure drills fail closed with deterministic exit codes:
     - Missing lockfile or toolchain mismatch fails closed (`VersionFreshnessError`, exit code 1).
     - Broken markdown links fail closed (`DocumentationDriftError`, exit code 1).
     - License violation or unsafe code in domain crates fails closed (`DependencyGroupError`, exit code 1).
     - Protected core path write attempt fails closed (`ProtectedPathError`, exit code 1).
     - Expired flaky test quarantine fails closed (`UnquarantinedFlakeError`, exit code 1).
     - Execution during paused state fails closed (`SchedulerPausedError`, exit code 2).
     - Stale commit merge attempt fails closed (`ExactCommitMismatchError`, exit code 1).
     - Autonomous publication attempt fails closed (`AutonomousPublicationViolationError`, exit code 1).
