# E0.2 local implementation acceptance — 2026-10-02

Scope: native workspace/API/config/runner/output local checks for the runnable
E0 synthetic skeleton. This is an implementation evidence record for coordinator
review; E0.4 phase acceptance is still required.

## Frozen public surface

- Parent workspace package: `careops-sim` 0.1.0, private/non-publishable.
- Library package: `careops-ed`; CLI binary/package: `careops-ed-cli` / `careops-ed`.
- Public JSON schema v1 and Rust APIs are in `crates/careops-ed`; CLI entry:
  `cargo run --locked -p careops-ed-cli -- run <scenario.json>`.
- Output is one JSON document on stdout with an input-byte SHA-256 manifest and
  run summary. Invalid arguments, input bytes, config or execution return nonzero
  and write diagnostics to stderr.
- P0 capacity/location v3 is strict and synthetic-only for execution; the
  runtime uses Kairos `Scheduler` and `SimTime`, with path dependencies to the
  pinned `kairo-ecs-core` and `kairo-ecs-types`.

## Integration to the accepted E0.1 contracts

The native schema tests exercise missing seed, unsupported schema version,
unsupported time unit, invalid counts/durations, unresolved references and
unknown fields. The native one-patient fixture has a hand-computable E0 slice:
arrival tick 1, start tick 1, completion tick 3, zero wait, two work ticks,
elapsed two ticks, and conserved count 1 completed / 0 unfinished. The accepted
E0.1 multi-stage second-based trace remains a future E1 oracle; this E0 slice
does not claim triage, assessment, treatment or discharge pathways.

The package graph is one-way: CareOps packages depend on public Kairos path
packages; Kairos manifests/source contain no CareOps package or parent path
dependency. The presentation layer is absent. Kairos source and parent submodule
pin are unchanged.

## Dependency and toolchain evidence

`Cargo.lock` uses version 3 for compatibility with the workspace MSRV Rust 1.76.
The direct dependencies are `serde 1.0.229`, `serde_json 1.0.151`, and
`sha2 0.10.9`; `sha2 0.11.0` was excluded because its declared Rust 1.85 MSRV
exceeds the parent 1.76 floor. Pinned Kairos is consumed by local path and no
Kairos source was edited. The parent workspace package repeats the pinned Kairos
root's Apache-2.0 license and repository metadata because these nested Kairos
crates inherit that metadata from their enclosing Cargo workspace. The CareOps
root package is `publish = false`; license ownership/release publication is not
asserted by this smoke increment.
