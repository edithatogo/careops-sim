## Source constraints and explicit policies

Kairos Flow supports incoming can_preempt plus victim preemptible(Suspend).
It has no resource-level consent flag: the ED adapter must enforce resource
consent and calendar eligibility before exposing a preempt-capable request.
Both clinical task policy and resource policy must permit interruption. Model
these as explicit booleans: incoming consent, incumbent consent, resource consent.
All three are required, and incoming urgency must be strictly greater. Equal
urgency never interrupts. Fixture policy version1 uses Suspend only; Restart and
Abort are distinct engine capabilities, not implicit clinical defaults.

Domain urgency is i32 descending; Flow priority_level is i32 ascending. Freeze
mapping priority_level = !urgency (bitwise complement), avoiding arithmetic
negation overflow at i32::MIN. Assert the two extremes, zero and ordering/ties.
Queue tie policy remains ready_tick ascending then request_id bytewise ascending.
Native integration must explicitly preserve domain ordering; Flow admission
sequence is not automatically the same as a domain request ID ordering.

Calendar phase order stays completion/release, calendar changes, interruption/
handover decisions and grants. No grant or preemption onto unavailable staff.
DrainActive keeps incumbent work running through a break/shift end; eligible
urgent work waits until a staff resource is available. No lower-capacity mutation
may violate Flow's active-claim bound. Completion at the same tick wins over
interruption or handover; do not emit a spurious zero-remaining segment.

A logical episode has one original sampled work amount and sampling lineage.
Suspend checkpoints useful work and resumes the remainder with no new draw.
Each staff capacity is one; every observed work interval must belong to exactly
one active claim. Waiting has no staff claim and is not service work. Preserve
all interruption/assignment history, not just final completion. Useful observed
work plus remaining work equals the original sample; clip observation at H,
while scheduled completion may lie beyond H. Do not double-count paused time.

## Explicit handover

Handover is a configured domain event, not an automatic Flow lease transfer.
For these fixtures it names logical episode, tick, incumbent and replacement.
It is allowed only for an active consenting episode on the named incumbent.
Replacement must satisfy the same zone/skill/calendar rules at the actual grant.
It may be busy or unavailable when the instruction occurs; the continuation waits
without holding a claim until it becomes eligible.
At a handover tick, stop/checkpoint the old segment, release its exact active
claim once, preserve logical episode and remaining work, then enqueue the new
segment for the named replacement. It can wait without holding either staff.
The released incumbent becomes available to other eligible work in that tick.
Do not simultaneously retain an old claim and wait for a replacement claim.

Flow Release checkpoints and terminally releases that request; Cancel also
checkpoints/removes its claim and terminally cancels it. Use Release for an
active handover segment. Never issue Cancel plus Release for the same claim.
A continuation gets a new request/work segment ID; its parent logical episode
and sample lineage persist. Actual API mechanics/notifications are reviewed in
E2.2. A released segment is not a completed patient/episode. No resampling and
no implicit zero-cost extra clinical work or handover overhead is assumed.

For this fixture policy there is at most one explicit handover per episode;
repeated/conflicting handover instructions are rejected. A handover request at
an episode's completion tick is a no-op with an explicit completed-before-handover
observation. If the logical episode has no active segment at that tick, record
not-active without manufacturing a claim. Missing/wrong identifiers remain
configuration errors. Require handover tick in [0,H], IDs from the staff contract,
and positive original work. More elaborate repeated handover is a later reviewed
policy, not inferred by a fixture validator.

## Model and fixture representation

Version1, synthetic provenance with explicit notes, integer ticks and fixed
positive work for these fixtures. IDs ASCII1..64, case-sensitive, no trimming or
normalisation. Apply the ID bound to staff, request, patient, zone and skill
identifiers. Cap32 skills per staff and32 required skills per request before
allocating lookup state. Staff: staff_id, assigned_zone, sorted unique skill IDs, shifts
and breaks as [start_tick,end_tick). Requests: request_id, patient_id, ready_tick,
assigned_zone, required_skills, urgency:i32, work_ticks:u64, required_staff_count=1.
Urgency is configured synthetic request priority, never an inferred clinical
acuity rule. No geographic movement or multi-zone permission is inferred.
Horizon H positive, requests ready before H; completions at H are observed and
new grants at H have zero observed work. Use u128 for sums/completion arithmetic.

Shifts must have positive length and not overlap for one staff member; adjacent
periods are allowed. Breaks must have positive length, not overlap, and be fully
contained within one shift. Declared intervals may end beyond H; observation clips
at H, configuration validity does not silently truncate them. A staff member may
have no shifts, meaning never available. Cap100000 requests,1024staff,1024calendar
intervals per staff and bound total event construction before allocating state.
Exact aggregate event budget is part of the later native interface contract;
fixtures include early cardinality rejection, not an invented exposed counter.

Each case records inputs, expected assignments/work intervals, unassigned/censored
rows, calendar-boundary observations and resource conservation. Negative cases
record diagnostic category and offending path, plus a repair group and an otherwise
identical valid control. Expected outcomes must be independently hand-derived;
validators checking file consistency are not the native simulator. Store a complete
case ID inventory and an explicit native-binding crosswalk.

## Dispatch and calendar semantics

At each relevant tick: complete work/release claims, apply calendar changes, then
grant new work. A request is eligible after ready_tick. Visit waiting requests by
urgency descending, ready_tick ascending, request_id bytewise ascending. For each,
choose the lowest staff_id among idle staff whose assigned_zone exactly matches,
whose skills include every required skill, and who are inside a shift and outside
all breaks. A higher-priority request with no eligible staff does not block a
lower-priority eligible one. Repeat until no eligible pair exists. Staff may hold
at most one active work assignment; waiting consumes no staff claim.

Default fixture in-flight policy is explicit version1 DrainActive: calendar
unavailability forbids new grants but active work continues to its actual end.
Do not shrink a Flow resource below active claims or manufacture a failed grant.
At a break or shift end, record active work overlapping that interval. Distinguish
break_overlap_ticks from work outside all shifts (shift_overtime_ticks). Their
union is scheduled_unavailable_work_ticks; disjoint shift/break rules prevent
double-counting. Do not invent a postponed break or pretend the policy proves
roster/clinical compliance. This is an explicit model approximation.

At an interval endpoint, half-open rules apply: no new grant at shift end/break
start; grants may start at shift start/break end. Work completing at such a boundary
releases normally; a replacement can start only if the resulting calendar permits.
A boundary at H still affects state/grants but contributes no time beyond H.
Handover and urgency preemption are mandatory separate E2.1.interrupt behaviors;
DrainActive here does not waive them. Cleaning/reservation is E2.1.space.

"""Local bounded gate capture; no dispatch or general harness claim."""
import datetime
import hashlib
import json
import os
from pathlib import Path
import re
import subprocess
import sys
import time

ROOT = Path(__file__).resolve().parents[2]
GATES = {
    "fixtures": ["python3", "-B", "-m", "unittest", "discover", "-s", "tests", "-p", "test_e21_interrupt.py", "-v"],
    "context": ["python3", "-B", "tools/context.py", "check"],
    "mvp": ["python3", "-B", "tools/mvp.py", "check"],
}
SOURCES = ["conductor/design/ed/e2-interrupt.json", "tests/test_e21_interrupt.py", "conductor/design/ed/e2-interrupt-crosswalk.md"]

def hashes():
    return {p: hashlib.sha256((ROOT / p).read_bytes()).hexdigest() if (ROOT / p).is_file() else None for p in SOURCES}

def write_new(path, value):
    with path.open("x") as stream:
        json.dump(value, stream, indent=2)
        stream.write("\n")

def main():
    if len(sys.argv) != 2 or sys.argv[1] not in GATES:
        raise SystemExit("choose fixtures, context, or mvp")
    gate = sys.argv[1]
    out = ROOT / ".artifacts/mvp/E2.1.interrupt.fixtures/logs"
    out.mkdir(parents=True, exist_ok=True)
    stem = f"{gate}-{time.time_ns()}-{os.getpid()}"
    log = out / (stem + ".log")
    record = {"gate": gate, "argv": GATES[gate], "cwd": str(ROOT),
              "head": subprocess.check_output(["git", "rev-parse", "HEAD"], cwd=ROOT, text=True).strip(),
              "python": sys.version, "start": datetime.datetime.now(datetime.timezone.utc).isoformat(),
              "source_hashes": hashes(), "log": str(log.relative_to(ROOT)), "status": "started"}
    write_new(out / (stem + "-started.json"), record)
    env = dict(os.environ, PYTHONDONTWRITEBYTECODE="1")
    command_exit_code = None
    with log.open("x") as stream:
        if gate == "fixtures" and not (ROOT / SOURCES[1]).is_file():
            stream.write("Gate refused: declared test file is missing.\n")
            exit_code = 2
            record["gate_error"] = "Refused: declared test file is missing"
        else:
            command_exit_code = subprocess.run(GATES[gate], cwd=ROOT, env=env, stdout=stream, stderr=subprocess.STDOUT).returncode
            exit_code = command_exit_code
    content = log.read_bytes()
    observed = re.search(rb"Ran (\d+) tests?", content)
    if gate == "fixtures" and exit_code == 0 and (not observed or int(observed.group(1)) == 0):
        exit_code = 2
        record["gate_error"] = "Successful command did not report a nonzero test count"
    after = hashes()
    if after != record["source_hashes"]:
        exit_code = 2
        record["gate_error"] = "Owned source changed during command"
    record.update(status="finished", end=datetime.datetime.now(datetime.timezone.utc).isoformat(),
                  exit_code=exit_code, command_exit_code=command_exit_code, log_sha256=hashlib.sha256(content).hexdigest(), source_hashes_after=after)
    result = out / (stem + "-result.json")
    write_new(result, record)
    print(json.dumps({"exit_code": exit_code, "receipt": str(result.relative_to(ROOT)), "log": record["log"]}))
    if exit_code:
        print(content.decode(errors="replace")[-3000:])
    return exit_code

if __name__ == "__main__":
    raise SystemExit(main())
