## Required preview oracles

1. native_preview_handles_v2_pending_disable_and_horizon_without_advancing:
   resource disabled at tick 0, waiting work submitted at 0 with duration 5,
   enable at 3. Preview and actual execution reach grant at 3 and completion at
   8. For horizon 6, stop before event 8; work is active/unfinished and Flow
   time remains at the last dispatched event (3). Do not step to 6 or invent
   a progress sample there.
2. native_preview_disabled_queue_has_no_next_event_or_completion: with a
   never-enabled queued request, dispatch both Disable0 and Submit0 events until
   no live scheduler entries remain. Then preview returns None, the request is
   still Waiting and no completion is fabricated.
3. c5_native_preview_preserves_pending_disable_and_completion: active work
   completion at 5 with disable at 2 and re-enable at 7. Legacy V1 capture
   rejects pending gate state. Production preview helper returns 2 and, after
   dispatch of disable, 5. Calling the helper must not mutate Flow time,
   dispatched-event count, claims/resource state or work progress. It takes no
   RNG, so cannot consume study RNG. Dispatch continues normally and work
   completes at 5.
4. c5_native_preview_limit_error_propagates_without_v1_fallback: with a
   gate-pending runtime use FlowCheckpointLimits { max_commands: 0, ..Default::default() }.
   The helper returns the capture error and must not retry legacy V1 capture.

All four named preview tests must be present, nonzero and observed passing in
test output. Include meaningful state comparisons around preview. No C5
user-task/config gate feature is claimed or implemented.
