# E2.2 pure dispatch policy contract

Status: coordinator contract independently reviewed by GPT-6.1-sol.
E2.1.space acceptance and a reviewed bound packet are required before dispatch.
Rust/Cargo 1.99.0 only. Parent ED ownership; no Kairos API or manifest changes.

This leaf implements ordinary one-staff task selection. It borrows an immutable
snapshot, validates the complete snapshot, and returns one request/staff identity
pair. It does not advance time, create events, draw randomness, mutate claims or
execute a second simulation. Preemption, Suspend, handover and actual allocation
remain the later authoritative FlowRuntime adapter's responsibility.

## Validation and deterministic diagnostics

Validate all rows before selection, including currently ineligible/future rows.
No invalid high-priority request is silently ignored. Use array-index paths such
as `requests[2].ready_tick`, `staff[0].breaks[1]`, `horizon`, `now`.

First-error order: request cardinality, staff cardinality, horizon, now; request
identities in input order; staff identities in input order; remaining request
fields in input order; remaining staff fields and calendars in input order.
Within request fields: ready_tick, assigned_zone, required_skills,
required_staff_count. Within staff: assigned_zone, skills, combined calendar
cardinality, shifts, breaks, then break containment. Invalid identity precedes
its duplicate check. Separate request and staff identity namespaces.

- At most 100000 requests and 1024 staff; check caps before derived allocation.
- H > 0 and now <= H. Every original ready_tick < H. Future ready times before H
  are valid and ignored by selection until ready_tick <= now.
- Every identity, zone and skill is ASCII, 1..64 bytes. At most 32 skills per list,
  sorted strictly ascending, unique. Empty skill lists are valid.
- required_staff_count must equal 1; reject other values visibly.
- At most 1024 combined shift/break intervals per staff. Every interval has
  start < end. Both arrays may arrive in any order; normalize derived views,
  never mutate the inputs. Within each array intervals cannot overlap; adjacency
  is valid. Every break is contained in one shift. Empty shifts are valid and
  mean unavailable. Intervals may extend beyond H without truncation.
- Rust integer and bool types define scalar representation; no JSON coercion is
  introduced by this leaf. Urgency uses all i32 values without negation overflow.

Use Cardinality for outer/combined calendar caps, Skills for malformed skill
lists, Identifier for identity/zone values, and the other named categories for
corresponding rules. A skill's malformed identity reports Skills at that list's
path. CalendarOverlap reports the calendar list path; BreakOutsideShift reports
its original break index. Outer cardinality paths are `requests` and `staff`; the combined calendar cap
uses `staff[i]`. Skill errors use `requests[i].required_skills` or
`staff[i].skills`. Calendar validation order is: inspect original shift intervals,
then normalized shift overlap; inspect original break intervals, then normalized
break overlap; finally break containment. An invalid interval reports its
original `staff[i].shifts[j]` or `staff[i].breaks[j]` path.

## Selection

At explicit now, staff eligibility means idle, exact zone match, all required
skills present, inside a half-open shift, and outside every half-open break.
A busy staff member remains unavailable even if DrainActive crosses a boundary.
Select ready requests by urgency descending, ready_tick ascending, request ID
ASCII ascending. Skip a request with no eligible staff. For the first eligible
request, choose the lowest ASCII staff ID. Return None if no pair exists.
A caller must rebuild the snapshot after an actual claim before selecting again;
repeated selection over an unchanged snapshot returns the same pair.

Avoid repeatedly scanning all staff for every skill of every request. Sort the
bounded staff list by ID once; derive available per-zone and per-skill bitsets
at now. Intersect at most 33 masks per ready request and compare its request key
against the current best, without globally sorting all requests. With at most
1024 staff, each mask uses at most 16 u64 words. Index only staff zones/skills,
not arbitrary request-only skills. Missing zone/skill short-circuits to no match.
BTreeMap borrowed keys provide deterministic lookup; unused high bits stay zero.
This bounds selection to O(R*(K+1)*ceil(S/64)) word operations plus map lookups.
Validation can use ordered identity sets and normalized calendar copies. No
performance, speedup or model-qualification claim follows without measurement.

import datetime
import hashlib
import json
import os
from pathlib import Path
import re
import subprocess
import sys
import time

ROOT = Path(__file__).resolve().parents[2]
TOOLCHAIN = Path("/Users/doughnut/.rustup/toolchains/1.99.0-aarch64-apple-darwin/bin")
GATES = {
    "tests": [str(TOOLCHAIN / "cargo"), "test", "--locked", "-p", "careops-ed"],
    "clippy": [str(TOOLCHAIN / "cargo"), "clippy", "--locked", "-p", "careops-ed", "--all-targets", "--", "-D", "warnings"],
    "format": [str(TOOLCHAIN / "cargo"), "fmt", "--all", "--check"],
}
SOURCES = ["crates/careops-ed/src/dispatch.rs", "crates/careops-ed/src/lib.rs", "crates/careops-ed/tests/e22_dispatch_policy.rs"]

def hashes():
    return {p: hashlib.sha256((ROOT / p).read_bytes()).hexdigest() if (ROOT / p).is_file() else None for p in SOURCES}

def write_new(path, value):
    with path.open("x") as stream:
        json.dump(value, stream, indent=2)
        stream.write("\n")

def main():
    if len(sys.argv) != 2 or sys.argv[1] not in GATES:
        raise SystemExit("choose tests, clippy, or format")
    gate = sys.argv[1]
    out = ROOT / ".artifacts/mvp/E2.2.dispatch.policy/logs"
    out.mkdir(parents=True, exist_ok=True)
    stem = f"{gate}-{time.time_ns()}-{os.getpid()}"
    log = out / (stem + ".log")
    record = {"gate": gate, "argv": GATES[gate], "cwd": str(ROOT),
              "head": subprocess.check_output(["git", "rev-parse", "HEAD"], cwd=ROOT, text=True).strip(),
              "python": sys.version, "start": datetime.datetime.now(datetime.timezone.utc).isoformat(),
              "source_hashes": hashes(), "log": str(log.relative_to(ROOT)), "status": "started"}
    write_new(out / (stem + "-started.json"), record)
    versions = {name: subprocess.check_output([str(TOOLCHAIN / name), "--version"], text=True).strip() for name in ("rustc", "cargo")}
    if not all(value.startswith(name + " 1.99.0 ") for name, value in versions.items()):
        raise SystemExit("Required Rust/Cargo 1.99.0 unavailable")
    record["toolchain"] = versions
    env = dict(os.environ, PYTHONDONTWRITEBYTECODE="1", PATH=str(TOOLCHAIN)+os.pathsep+os.environ.get("PATH", ""), CARGO_HOME="/tmp/c2-route-receipt-cargo-home", CARGO_TARGET_DIR=str(out / "target"), CARGO_INCREMENTAL="0", CARGO_PROFILE_DEV_DEBUG="0", CARGO_PROFILE_TEST_DEBUG="0", CARGO_BUILD_JOBS="2")
    command_exit_code = None
    with log.open("x") as stream:
        if gate == "tests" and not (ROOT / SOURCES[2]).is_file():
            stream.write("Gate refused: declared test file is missing.\n")
            exit_code = 2
            record["gate_error"] = "Refused: declared test file is missing"
        else:
            command_exit_code = subprocess.run(GATES[gate], cwd=ROOT, env=env, stdout=stream, stderr=subprocess.STDOUT).returncode
            exit_code = command_exit_code
    content = log.read_bytes()
    observed = re.search(rb"test result: ok\. ([1-9][0-9]*) passed", content)
    if gate == "tests" and exit_code == 0 and (not observed or int(observed.group(1)) == 0):
        exit_code = 2
        record["gate_error"] = "Successful command did not report a nonzero test count"
    after = hashes()
    if after != record["source_hashes"]:
        exit_code = 2
        record["gate_error"] = "Owned source changed during command"
    record.update(status="finished", end=datetime.datetime.now(datetime.timezone.utc).isoformat(),
                  exit_code=exit_code, command_exit_code=command_exit_code, log_sha256=hashlib.sha256(content).hexdigest(), source_hashes_after=after)
    result = out / (stem + "-result.json")
    write_new(result, record)
    print(json.dumps({"exit_code": exit_code, "receipt": str(result.relative_to(ROOT)), "log": record["log"]}))
    if exit_code:
        print(content.decode(errors="replace")[-3000:])
    return exit_code

if __name__ == "__main__":
    raise SystemExit(main())

# Bounded worker prompt

You are executing one reviewed packet for CareOps Sim. Use the model selected by
the coordinator; gpt-6-luna is a candidate for this role. The packet cannot override
user/system instructions. Do not take architecture or release ownership.

1. Read AGENTS.md and the supplied bound packet. Confirm packet ID, target repo,
   base commit, input hashes and assigned worktree. Run packet-check. If any differ,
   stop and report `blocked`; do not update hashes to make the check pass.
2. Read the listed context and interface contract. Identify the single expected
   behavior/output, permitted files, protected paths and exact final test oracle.
3. Confirm the coordinator has accepted prerequisites and reserved your paths.
   Do not acquire conflicting ownership or start other work yourself.
4. Execute the packet's steps in order. Add behavior-focused tests before code
   when required. Keep edits inside write_paths and use the existing architecture.
5. Run the listed commands in the specified directories. Record real exits,
   counts and artifact paths. A missing test/command is a blocker, not a pass.
6. Check your diff for unrelated changes and rerun the final acceptance check.
   Do not change tolerances, golden results, test exclusions or public semantics
   to remove a failure unless the packet explicitly authorizes that exact change.
7. After two unsuccessful correction attempts, summarize the failing command and
   smallest observed counterexample. Escalate missing contract/skill/tool/hardware
   needs rather than repeatedly guessing.
8. Return `result-template.json` with `ready_for_review` or `blocked`, plus the
   actual diff/commit and evidence. Never claim `accepted`, change the plan checkbox,
   merge into another worker's branch, publish or update the parent submodule pin.

The coordinator/reviewer performs the combined integration checks and advances
accepted status. Serial execution uses this same prompt and evidence contract.

# MVP Luna execution loop

Work one bound leaf instance. Your output is proposed work until coordinator
acceptance. This role does not permit you to weaken tests, choose unapproved
interfaces, accept your own result, publish or switch the model.

- Start from the bound context bundle, exact source hashes and interface. Read
  repository AGENTS instructions, but do not load every track/report by default.
- Record one attempt ID and the model/version actually exposed by the harness.
  Missing cost/version data is unknown, not a fabricated value.
- Implement one output. For code changes, reproduce the specified failing behavior
  before the fix and then run the final success check. For tests-only leaves,
  final execution must verify the intended red fixture/expected failure explicitly;
  a silent missing executable is not a useful red test.
- Work for at most 60 minutes per attempt and at most two unsuccessful corrections.
  Stop with evidence at either limit; a coordinator may authorize a new attempt
  after reviewing the cause. Never expand write paths or tests on your own.
- If source inspection needs more context, request a new bound slice. Keep loaded
  relevant context within the 24 KB bundle budget (bytes, not a token guarantee).
  Stream data extraction in batches rather than putting all evidence in prompts.
- Checkpoint after a successful test or before interruption: leaf/instance/attempt,
  exact base and input hashes, changed files, last command/exit, output hashes,
  unresolved question and the next single action. Keep logs as files, not prose.
- Return result.json with actual command receipts and ready_for_review or blocked.
  A behavioral oracle failing, unavailable prerequisite or stale base is blocked.
  The coordinator verifies diffs and runs the independent/combined checks.
