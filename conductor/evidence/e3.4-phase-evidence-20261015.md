## Phase evidence summary

- **E3.1 Public API, CLI Suite, and Deterministic Errors (PR #113, PR #114)**:
  - CLI subcommands implemented and validated: `validate`, `run`, `compare`, `export`.
  - Deterministic exit codes and diagnostic messages:
    - `0`: Success.
    - `2`: Invalid argument or usage error (e.g. missing scenario path).
    - `3`: Scenario or input file not found.
    - `4`: Malformed scenario configuration (fails schema or invariant validation).
    - `5`: Destination file exists without `--force` (overwrite protection).
  - Overwrite protection: `--force` required when writing to an existing destination file.
  - Parameter and horizon overrides: `--seed <N>` and `--horizon <N>` flags override scenario settings without editing JSON files.
  - Run comparison oracle (`compare_runs`): compares metrics between two runs, computing absolute and relative percentage differences with explicit units and denominators. Rejects comparison across incompatible scenarios with clear diagnostic error.
  - Fresh-user walkthrough and `--help` CLI documentation tested for all subcommands.

- **E3.2 Multi-Worker Runner, Checkpointing, and Progress (PR #115, PR #117)**:
  - CLI subcommand implemented: `batch <scenario.json>`.
  - Independent CPU worker thread pool: distributes independent replications across 1, 2, or N workers.
  - Multi-worker deterministic equivalence: verified that 1-worker, 2-worker, and 4-worker execution produce identical mean wait, standard error, and replication metrics for identical base seeds.
  - Atomic checkpoint persistence: `--checkpoint <N>` interval saves intermediate state atomically via temporary file and atomic rename.
  - Resumption from checkpoint: `--resume <checkpoint.json>` recovers completed replications and resumes pending replications without re-running completed seeds.
  - Corrupted and tampered checkpoint rejection: rejects checkpoints with negative total replications, out-of-bounds pending indices, or hash mismatches.
  - Atomic artifact writes: runs write to temporary files first (`.partial`), renaming atomically upon full completion; partial or interrupted runs cannot be mistaken for valid finished experiments.

- **E3.3 Arrow/Parquet Export, Metric Denominators, and Spatial Summaries (PR #118, PR #119)**:
  - Native Arrow tabular schema generation without external heavy crates:
    - `careops.ed.patient_record.v1`: patient journeys, acuities, arrival/triage/bed/departure ticks, wait/elapsed ticks with explicit denominators.
    - `careops.ed.metrics.v1`: metric records carrying units, metric denominators (`started_patients`, `completed_patients`, `total_arrivals`, `horizon_ticks`), statistical uncertainty (variance, standard error, 95% confidence intervals `ci_95_lower` and `ci_95_upper`), and censored/unfinished counts.
    - `careops.ed.spatial_transit.v1`: location transit records carrying `from_location`, `to_location`, `distance_metres`, departure/arrival ticks, spatial revision, and explicit `PositionKind`.
  - Parquet DDL schema definitions (`generate_parquet_schema_ddl`) for downstream Parquet/DuckDB consumers.
  - Trajectory position kinds: distinguishes `Observed` (EHR/ground-truth), `Simulated` (direct agent transit simulation), and `Interpolated` (sub-tick trajectory interpolation).
  - Spatial summary calculation: computes per-edge and per-location traversal counts, total distance travelled, and average transit speed, exported to CSV (`export_spatial_summary_to_csv`).
  - Batch and export CLI integration: `--export-arrow <PATH>`, `--export-spatial <PATH>`, and `--spatial-rev <REV>` flags wired into the CLI `batch` command; `--format arrow` and `--format parquet` wired into `export`.
  - Deterministic equivalence across 1, 2, and 4 workers for full Arrow export bundles.
  - Resumption equivalence: resumed batches produce Arrow export bundles and spatial summaries that match uninterrupted baselines.
