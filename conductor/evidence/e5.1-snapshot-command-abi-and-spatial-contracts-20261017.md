## 1. Executive Summary & Disposition

Task E5.1 freezes the architectural and protocol contract between the native Kairos discrete-event simulation engine and downstream interactive visualization surfaces (PixiJS web dashboard, headless replay tooling, and WebSocket telemetry services).

### Core Accomplishments
1. **Narrow Snapshot & Command ABI (`careops_ed.abi.v1`)**:
   - Frozen minimal, decoupled message protocol encompassing state snapshots, incremental deltas, idempotent commands, command acknowledgments, progress telemetry, and error envelopes.
   - Lossless wide integer serialization: virtual time / simulation ticks ($u128$) and entity identifiers ($u64$) are serialized to JSON as decimal strings (`U128Tick`), eliminating JavaScript IEEE 754 `float64` mantissa truncation beyond $2^{53}-1$ ($9,007,199,254,740,991$).
   - Rigorous sequencing and gap detection: incremental deltas specify both monotonic sequence number (`seq`) and base sequence (`base_seq`). Packet loss or sequence gaps cleanly trigger a `ResyncRequired` state machine transition prompting full snapshot recovery.
   - Idempotent command processing: command envelopes carry client-generated UUIDs (`command_id`); a bounded deduplication store prevents duplicate execution on network retry, returning `DuplicateIgnored` acknowledgments without state corruption.
   - Safe cancellation protocol: explicit cancellation command halts simulation advancement, locks runner state in `Cancelled`, and emits progress telemetry with `cancelled = true`.

2. **Shared Spatial Package Contract (`careops_ed.spatial.v1`)**:
   - Multi-layer separation: physical boundary geometry, topological route graph, and clinical operational resource bindings are bound under a single versioned spatial package.
   - Local metric coordinate frame: all coordinates are expressed in integer millimeters (`x_mm`, `y_mm`, `z_mm` / floor levels), guaranteeing cross-platform bit-level determinism between native Rust and WebAssembly targets without floating-point drift.
   - Cryptographic revision binding: packages embed a canonical SHA-256 revision hash (`spatial_revision`); handshake negotiation fails closed if client and simulation revisions mismatch.
   - Canonical two-room synthetic layout fixture (`synthetic_layout_v1.json`) delivered with verified coordinate geometry, route topology, and clinical locations (`LOC-TRIAGE-01`, `ROOM-RESUS-01`, `BAY-ACUTE-01`, `BAY-ACUTE-02`, `CORRIDOR-MAIN`, `WAITING-ROOM-01`).

3. **FFI, Memory/Buffer Lifetime & Browser Support Review**:
   - Memory management across Wasm/JS boundary uses zero-copy byte buffers and isolated string boundaries, preventing lingering C pointers and heap leaks.
   - Runtime backpressure controls: message payloads are bounded to 1MB, queue depths to 1,000 messages, and rendering frame rates (off / 30 / 60 FPS) operate independently from simulation engine stepping.
   - Supported browser matrix frozen: Chrome 110+, Firefox 110+, Safari 16.4+, Edge 110+ (requiring BigInt, WebSocket, and WebAssembly 1.0/2.0). Unsupported environments (IE11, browsers lacking BigInt) fail closed.

### 2.2 Wide Integer Lossless Representation

JavaScript runtimes utilize standard IEEE 754 double-precision floating-point numbers (`float64`) for all numeric literals. The maximum safe integer representable without precision loss is:
$$\text{MAX\_SAFE\_INTEGER} = 2^{53} - 1 = 9,007,199,254,740,991$$

CareOps ED simulation ticks are represented internally as $u128$ nanoseconds or discrete simulation steps. For long-horizon runs or nano-second timestamps, values easily exceed $2^{53}-1$:
- $2^{53} = 9,007,199,254,740,992$ (boundary)
- $2^{64}-1 = 18,446,744,073,709,551,615$ (standard u64 tick)
- $2^{120} = 1,329,227,995,784,915,872,903,807,060,280,344,576$ (extended u128 horizon)

Under standard JSON number serialization, JavaScript `JSON.parse` truncates low-order bits:
$$\text{Number}("9007199254740993") \implies 9007199254740992$$

To ensure absolute cross-platform mathematical integrity:
1. All $u128$ tick fields (`tick`, `effective_tick`, `mean_wait_ticks`, `tick_current`, `tick_horizon`) are strictly encoded as decimal strings matching `^[0-9]+$`.
2. TypeScript consumers deserialize these directly to native JavaScript `BigInt(str)`.
3. Rust harnesses deserialize strings to `U128Tick` wrappers dereferencing to `u128`.

Bit-level round-trip tests confirm zero-loss identity across all integer ranges.

## 3. Sequencing, Resync & Idempotent Commands

### 3.1 Sequencing & Gap Detection State Machine

```
              +----------------------+
              |  Initial Handshake   |
              +----------+-----------+
                         | (Receives Snapshot seq=N)
                         v
              +----------------------+
       +----->|  Connected / Synced  |<----+
       |      +----------+-----------+     |
       |                 |                 |
(Delta seq=K+1,          | (Delta seq=K+M, | (Snapshot seq=S,
 base_seq=K)             |  base_seq != K) |  base_seq=S)
       |                 v                 |
       |      +----------------------+     |
       +------|    ResyncRequired    |-----+
              | (Emits Resync Command|
              +----------------------+
```

1. **Normal Flow**: Each incoming delta must satisfy `delta.base_seq == client.last_seen_seq`. Upon acceptance, `client.last_seen_seq = delta.seq`.
2. **Gap Detection**: If `delta.base_seq != client.last_seen_seq`, network packet loss or dropped frames have occurred. The client immediately transitions to `ResyncRequired` and dispatches `RequestSnapshotCommand`.
3. **Stale / Duplicate Deltas**: If `delta.seq <= client.last_seen_seq`, the packet is harmlessly ignored without mutating client state.

### 3.2 Idempotent Command Processing

Network retries or reconnects can cause duplicate command delivery. To prevent catastrophic side effects (such as double-incrementing bed counts or double-canceling runs):
- Every command carries a globally unique `command_id` (UUID).
- The server maintains a bounded FIFO ring buffer (`IdempotentCommandStore`) tracking the latest 1,024 command outcomes.
- When an already-executed `command_id` is received, the server bypasses model mutation and re-emits the original acknowledgment with `status: DuplicateIgnored`.

## 5. FFI Needs, Buffer Lifetimes & Browser Targets

### 5.1 FFI Memory & Buffer Lifetimes
- **Boundary Contract**: Rust-native engine exposes C/Wasm ABI interfaces where input strings are consumed by value and output buffers are returned as explicit JSON strings.
- **Zero Memory Leaks**: All allocated strings across FFI boundaries are cleanly freed by explicit release hooks or owned Wasm linear memory scopes.
- **Backpressure & Slow Consumers**:
  - Maximum WebSocket envelope size: $1\text{ MB}$.
  - Maximum pending command queue depth: $1,000$ messages.
  - Visualization frame rendering (PixiJS) is decoupled from simulation advancement: slow clients drop intermediate visual frames without stalling the backend simulation.
