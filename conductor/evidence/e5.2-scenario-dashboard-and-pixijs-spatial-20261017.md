## 1. Executive Summary & Disposition

Task E5.2 delivers the complete interactive scenario dashboard (`apps/dashboard`), integrating parameter authoring, simulation execution, comparative outcome analysis, multi-format export, and 2D spatial layout presentation with PixiJS canvas and accessible SVG fallbacks.

### Core Accomplishments
1. **Scenario Edit, Run, Compare & Export Architecture (`apps/dashboard/src/scenario/`)**:
   - Schema-validated editor for ED arrival processes, triage acuity distributions (ATS 1–5), bed allocations (resus, acute, subacute), and clinical staffing rosters (RNs, physicians).
   - Actionable troubleshooting diagnostics without author assistance: detects zero capacity (`ZERO_BED_CAPACITY`), negative horizons (`NON_POSITIVE_HORIZON`), unnormalized triage distributions (`SUM_NOT_ONE`), and empty labels (`EMPTY_NAME`), returning clear suggested fixes.
   - Controlled scenario comparison engine: evaluates nominal ($4.5\text{ arr/h}$) versus surge ($12.0\text{ arr/h}$) conditions, computing signed deltas, percentage changes, wait time inflation ($>2.0\times$), peak bed saturation ($>95\%$), and standard errors.
   - Multi-format exporters: JSON run documents (`careops_ed.run_document.v1`), CSV tabular comparisons, and Apache Arrow telemetry schemas.

2. **2D Spatial View & Overlay Engine (`apps/dashboard/src/spatial/`)**:
   - Consumes the shared spatial package (`synthetic_layout_v1.json`) conforming to `careops_ed.spatial.v1`.
   - Local metric coordinate projection: transforms integer millimeters (`x_mm`, `y_mm`) to viewport display coordinates at $0.05\text{ px/mm}$.
   - Spatial visual overlays: room occupancy heatmaps ($[0.0, 1.0+]$ color ramp), priority queue depth badges, and metric route transit polylines.
   - Strict data provenance enforcement: tracks entity position provenance (`simulated`, `observed`, `interpolated`, or `unknown`). Unknown positions remain visibly marked as "unknown" without inventing coordinates.

3. **WCAG 2.1 AA Accessible Data Tables (`apps/dashboard/src/spatial/accessible_tables.ts`)**:
   - Full screen-reader-accessible semantic HTML equivalents for all spatial overlays (Room Occupancy, Waiting Queues, Active Entity Tracking).
   - Employs `<table role="region">`, captions, column/row scope headers, and ARIA labels, guaranteeing zero information asymmetry between graphical overlays and assistive technology.

4. **Recorded Simulation Replay Engine (`apps/dashboard/src/replay/replay_engine.ts`)**:
   - Frame-by-frame replay of native Kairos simulation outputs (`nominal_mvp.json`, `surge_mvp.json`).
   - Clock decoupling: frame rendering rate (off / 30 / 60 FPS) is strictly separated from discrete simulation advancement.
   - Non-destructive scrubbing and seeking: scrubs directly to recorded simulation ticks without modifying backend event logs or synthesizing artificial movement.
   - Playback rate controls: $0.5\times, 1.0\times, 2.0\times, 5.0\times$, paused, and single-step forward/backward.

5. **Live WebSocket Telemetry & Remote Commands (`apps/dashboard/src/live/websocket_client.ts`)**:
   - Client-side protocol implementation of `careops_ed.abi.v1`.
   - Dispatches remote commands (`pause`, `resume`, `step`, `set_speed`, `cancel`, `inject_patient`) with `command_id` and `client_nonce`.
   - Automatic sequence gap detection and snapshot resync.
   - Bounded client ring buffer ($1,000$ messages) preventing memory growth.

## 3. Spatial Presentation, Overlays & Provenance

### 3.1 Shared Layout Topology (`synthetic_layout_v1.json`)

The dashboard loads canonical synthetic geometry:
- Units: Integer millimeters (`x_mm`, `y_mm`, `z_mm`).
- Bounding Box: $(0, 0)$ to $(12000, 12000)$ mm ($12\text{m} \times 12\text{m}$).
- Locations:
  - `WAITING-ROOM-01`: $(2000, 2000, 0)$ mm, bounds $[0, 0]$ to $[4000, 4000]$ mm.
  - `LOC-TRIAGE-01`: $(6000, 2000, 0)$ mm, bounds $[4000, 0]$ to $[8000, 4000]$ mm.
  - `CORRIDOR-MAIN`: $(6000, 6000, 0)$ mm, bounds $[0, 4000]$ to $[12000, 8000]$ mm.
  - `BAY-ACUTE-01`: $(2000, 10000, 0)$ mm, bounds $[0, 8000]$ to $[4000, 12000]$ mm.
  - `BAY-ACUTE-02`: $(6000, 10000, 0)$ mm, bounds $[4000, 8000]$ to $[8000, 12000]$ mm.
  - `ROOM-RESUS-01`: $(10000, 10000, 0)$ mm, bounds $[8000, 8000]$ to $[12000, 12000]$ mm.
- Shortest path routing: All route nodes are interconnected through the central circulation corridor with verified metric distances ($4,000\text{ mm}$ per segment).

### 3.2 Provenance Boundaries

The dashboard explicitly enforces four discrete data provenance tiers:
1. `observed`: Extracted from empirical or fixture event logs.
2. `simulated`: Produced directly by discrete-event simulation scheduler events.
3. `interpolated`: Computed intermediate graphical positions between discrete simulation frames.
4. `unknown`: Entities lacking verified spatial bindings (e.g. unassigned patients, external transfers).
   - Unknown coordinates are strictly rendered as `(Unknown)`, never assigned $(0, 0)$ or fabricated coordinates.

## 5. Replay Engine & Decoupled Clocks

```
+-----------------------------------+-----------------------------------+
| Simulation Engine Time (Ticks)    | Presentation Frame Clock (FPS)    |
+-----------------------------------+-----------------------------------+
| Discrete integer simulation steps | 60 FPS, 30 FPS, or Off (headless) |
| Advances on discrete events       | Refreshes display at fixed rate   |
| Scrubbing restores exact frame    | Interpolates smooth motion        |
| Deterministic event ordering      | Zero effect on simulation model   |
+-----------------------------------+-----------------------------------+
```

- **Frame Rate Independence**: Setting render rate to 0 FPS (headless), 30 FPS, or 60 FPS has zero impact on simulation event order or metric outcomes.
- **Scrubbing & Seeking**: Seeking to tick $T$ selects the exact frame at $\le T$, preventing synthetic interpolation of non-existent event states.
- **Speed Multipliers**: Supports $0.5\times, 1.0\times, 2.0\times, 5.0\times$ playback without mutating underlying tick deltas.
