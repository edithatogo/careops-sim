1. **Chosen Kernel with Measurable End-to-End Benefit (`K-TRANSIT`)**:
   - Evaluates batched Euclidean/Manhattan topological transit times, vector norms, velocities, and waypoint horizons across hundreds to thousands of moving clinical entities over the spatial layout established in Phase E5.
   - High arithmetic intensity (FLOPs / byte) offsets API-level staging and synchronisation costs, achieving break-even at batch sizes $N^* \approx 1,024$ and delivering measurable end-to-end speedups ($S_{\mathrm{e2e}} \ge 2.2\times$ at $N=16,384$; $S_{\mathrm{e2e}} \ge 4.5\times$ at $N=262,144$).
2. **Secondary Resident Acceleration Kernel (`K-CAND`)**:
   - Evaluates multi-candidate calibration objective scores across parameter variations ($M \in [8, 128]$) against reference observation arrays ($N \in [4,096, 65,536]$).
   - Ingress is amortized across $k \ge 10$ optimization iterations with resident GPU buffers, yielding $S_{\mathrm{resident}} \ge 3.5\times$ to $8.2\times$.
3. **Explicit Rejection of Standalone Low-Batch Reductions**:
   - Micro-batch reductions ($N \le 256$) such as presorted 1D Wasserstein-1 (`K-W1-PRESORT`) exhibit severe negative speedups ($S_{\mathrm{e2e}} \le 0.1\times$) due to fixed driver encoding and buffer mapping latencies ($T_{\mathrm{overhead}} \approx 10\,\mu\mathrm{s}$ vs $T_{\mathrm{CPU}} \le 0.5\,\mu\mathrm{s}$). These remain strictly on multicore CPU unless embedded inside resident chains.

### 2.2 Rigorous Separation of Presorted W1 from Weighted/Full-Sort W1

A critical governance requirement from Report 26 is preventing **sorting overhead from being disguised as reduction efficiency**:

1. **Presorted Equal-Size W1 (`K-W1-PRESORT`)**:
   $$W_1(u, v) = \frac{1}{N} \sum_{i=1}^N |u_i - v_i|$$
   Operates strictly on vectors that are guaranteed to be sorted upstream. Its computational complexity is $O(N)$ arithmetic subtractions and accumulations. When operands are already resident in GPU memory, device reduction executes in microseconds.
2. **General Weighted / Unequal-Size W1 (`K-W1-WEIGHTED`)**:
   $$W_1(F_u, F_v) = \int_0^1 |F_u^{-1}(t) - F_v^{-1}(t)|\,dt = \sum_{k=1}^{N_u + N_v - 1} |x_k - y_k| \cdot \Delta t_k$$
   Requires merging non-uniform support points and integrating step-wise cumulative distributions across unequal sample sizes ($N_u \neq N_v$). It involves irregular non-coalesced memory lookups or parallel search scans.
3. **Full Sort Pipeline (`K-SORT-FULL`)**:
   Unordered raw samples must first undergo radix or bitonic sorting ($O(N \log N)$) before reduction. In benchmark measurements, the sorting phase accounts for $78\%$ to $86\%$ of total execution time.
4. **Contractual Prohibition**:
   Reporting $W_1$ reduction speedup as end-to-end calibration speedup without including sorting or empirical CDF generation is strictly rejected.

## 3. Data/Execution Contract Classes & Tolerance Freeze (`D0` – `D5`)

To prevent non-deterministic simulation drift while permitting numerical acceleration, Task E6.1 defines and freezes Contract Classes `D0` through `D5`:

```
+----------------------------------------------------------------------------------------------------+
|                                    Contract Classes D0 - D5                                        |
+-------+-----------------------------+------------------------------------+-------------------------+
| Class | Designation                 | Concrete Contract Scope            | Tolerance / Gate Rule   |
+-------+-----------------------------+------------------------------------+-------------------------+
| D0    | Authoritative Exact State   | Clock, event queue, RNG, IDs       | Bitwise CPU identical   |
| D1    | Exact Integer Outputs       | Histograms, prefix count scans     | Bitwise identical (==)  |
| D2    | Floating Elementwise        | Loss, residuals, spatial transit   | |err| <= 1e-6, ULP <= 2 |
| D3    | Reductions & Objectives     | W1, KS distance, calibration error | |err| <= 1e-5, Metric   |
| D4    | Decision Stability          | Parameter candidate rankings       | Spearman rho >= 0.999   |
| D5    | Repeated Execution          | Determinism across 100 runs        | Zero run-to-run drift   |
+-------+-----------------------------+------------------------------------+-------------------------+
```

### 3.1 D0: Authoritative Exact State Contract
- **CPU Ownership**: Monotonic virtual time ($\mathrm{tick}_{ns} \in \mathbb{N}$), causal discrete-event queues, priority FIFO order, and pseudo-random number generator (PRNG) state are owned strictly by the CPU.
- **RNG Determinism**: Accelerators are never permitted to advance stochastic streams or generate replacement random numbers. Host generates fixed input buffers deterministically.

### 3.2 D1: Exact Integer Numeric Outputs
- **Bitwise Exactness**: Integer histogram binning (`K-HIST`) and prefix scans (`K-SCAN`) must evaluate to identical bit representations:
  $$\mathrm{counts}_{\mathrm{actual}}[b] = \mathrm{counts}_{\mathrm{expected}}[b] \quad \forall b \in [0, B-1]$$
- **Conservation Law**: Total bin count must strictly conserve sample count: $\sum_{b=0}^{B-1} \mathrm{counts}[b] \equiv N$.
- **Overflow Protection**: Accumulations must use saturating or checked $u64$ arithmetic to prevent silent integer wrap-around.

### 3.3 D2: Floating Elementwise Tolerances
- **Boundaries**: Elementwise residuals, clamping transforms, and spatial transit durations:
  $$\max_{i} |y_i - \hat{y}_i| \le 10^{-6} \quad (\text{absolute tolerance})$$
  $$\max_{i} \frac{|y_i - \hat{y}_i|}{|y_i| + \epsilon} \le 10^{-5} \quad (\text{relative tolerance, for } |y_i| > 10^{-12})$$
- **ULP Tracking**: Units in the Last Place (ULP) distance is monitored for IEEE 754 $f32$:
  $$\mathrm{dist}_{\mathrm{ULP}}(a, b) \le 2 \quad \text{for standard arithmetic transforms}$$

### 3.4 D3: Reductions & Calibration Objectives
- **Tolerance**: Objective difference compared against 64-bit float reference:
  $$|W_{1,\mathrm{actual}} - W_{1,\mathrm{reference}}| \le 10^{-5}, \quad |D_{\mathrm{KS},\mathrm{actual}} - D_{\mathrm{KS},\mathrm{reference}}| \le 10^{-5}$$
- **Metric Axioms Enforced**:
  - *Non-negativity*: $W_1(u, v) \ge 0$ and $D_{\mathrm{KS}}(u, v) \ge 0$.
  - *Identity of indiscernibles*: $W_1(u, u) = 0.0$.
  - *Symmetry*: $|W_1(u, v) - W_1(v, u)| \le 10^{-12}$.
  - *Triangle inequality*: $W_1(u, w) \le W_1(u, v) + W_1(v, w) + 10^{-5}$.

### 3.5 D4: Decision Stability Contract
- **Rank Correlation**: Candidate parameter set rankings across $M \ge 8$ evaluations must maintain:
  $$\rho_{\mathrm{Spearman}} = 1 - \frac{6 \sum d_i^2}{M(M^2 - 1)} \ge 0.999$$
- **Zero Top-Candidate Flip**: The winning parameter set (Rank 1) selected by the device path must be identical to the winning parameter set selected by the CPU reference:
  $$\mathrm{argmin}_m (\mathrm{score}_m^{\mathrm{device}}) \equiv \mathrm{argmin}_m (\mathrm{score}_m^{\mathrm{cpu}})$$

### 3.6 D5: Repeated Execution Determinism
- **100-Run Repeatability**: Executing identical inputs across $100$ runs on a fixed backend must produce bit-identical results for integer workloads and zero ULP drift for floating-point workloads.

## 4. Data-Movement Economics & Break-Even Formulations

### 4.1 Unified Physical Memory vs API-Level Staging/Readback

A central finding of Report 26 is that Apple Silicon's Unified Memory Architecture (UMA) **eliminates PCIe bus bottleneck but does not eliminate API-level data movement**:
- `wgpu` (`Queue::write_buffer`) copies host bytes into internal command staging allocations.
- Buffer readback (`Buffer::map_async`) introduces an explicit GPU execution fence and CPU cache-invalidation barrier.
- Consequently, GPU dispatch incurs fixed overheads:
  - $T_{\mathrm{ingress}}^{\mathrm{fixed}} \approx 2.0\,\mu\mathrm{s}$
  - $T_{\mathrm{kernel}}^{\mathrm{fixed}} \approx 3.0\,\mu\mathrm{s}$ (pipeline submission, command encoder commit)
  - $T_{\mathrm{sync/readback}}^{\mathrm{fixed}} \approx 5.0\,\mu\mathrm{s}$ (fence polling, buffer mapping)

### 4.2 Analytical Timing Decomposition

Total end-to-end execution time on device:
$$T_{\mathrm{e2e}}(N) = T_{\mathrm{cold}} + T_{\mathrm{ingress}}(N) + T_{\mathrm{kernel}}(N) + T_{\mathrm{sync/readback}}(N)$$

where:
- $T_{\mathrm{cold}}$: Shader pipeline compilation and bind group layout caching (amortized over simulation lifecycle).
- $T_{\mathrm{ingress}}(N) = T_{\mathrm{ingress}}^{\mathrm{fixed}} + \frac{N \cdot \mathrm{bytes}_{\mathrm{in}}}{\mathrm{BW}_{\mathrm{mem}}}$.
- $T_{\mathrm{kernel}}(N) = T_{\mathrm{kernel}}^{\mathrm{fixed}} + \frac{N}{\mathrm{throughput}_{\mathrm{device}}}$.
- $T_{\mathrm{sync/readback}}(N) = T_{\mathrm{sync/readback}}^{\mathrm{fixed}} + \frac{N \cdot \mathrm{bytes}_{\mathrm{out}}}{\mathrm{BW}_{\mathrm{mem}}}$.

### 4.3 Break-Even Speedup Formulations

1. **One-Shot End-to-End Speedup**:
   $$S_{\mathrm{e2e}}(N) = \frac{T_{\mathrm{CPU,multicore}}(N)}{T_{\mathrm{ingress}}(N) + T_{\mathrm{kernel}}(N) + T_{\mathrm{sync/readback}}(N)}$$

2. **Resident Chain Speedup (Amortized over $k$ Steps)**:
   $$S_{\mathrm{resident}}(N, k) = \frac{\sum_{i=1}^k T_{\mathrm{CPU,multicore}, i}(N)}{T_{\mathrm{ingress}}(N) + \sum_{i=1}^k T_{\mathrm{kernel}, i}(N) + T_{\mathrm{readback}}(N)}$$

### 4.4 Break-Even Curves Across Workload Families

```
Speedup S

   |                                               *      * CAND-25 (Transit 262k)
```

- **One-Shot Break-Even Threshold**: $N^* \approx 1,024$ for spatial transit evaluation (`K-TRANSIT`) and $N^* \approx 40,000$ for simple elementwise transforms (`K-ELT`).
- **Resident Chain Break-Even**: For multi-candidate scoring (`K-CAND`), keeping observation buffers resident across $k=100$ iterations reduces the break-even threshold to $N^* \approx 256$, delivering $S_{\mathrm{resident}} = 3.85\times$ ($M=32$) and $S_{\mathrm{resident}} = 8.20\times$ ($M=128$).

## 5. Hardware Fallback & Unavailable-Device Behavior

To ensure continuous integration reliability across all platforms (including headless Linux CI, non-Apple developers, and environments lacking Metal or Vulkan hardware), Task E6.1 establishes a strict zero-panic fallback architecture:

```
+----------------------------------------------------------------------------------------------------+
|                                    Compute Dispatch Architecture                                   |
+----------------------------------------------------------------------------------------------------+
|                                 NumericBatchExecutor Facade                                        |
|                                              |                                                     |
|                +-----------------------------+-----------------------------+                       |
|                | [Device Configured & Metal]                               | [Fallback / Absent]   |
|                v                                                           v                       |
|        wgpu / Metal Device                                         CpuFallbackCompute              |
|        (Task E6.2 Device Path)                                     (Pure Rust Standard Lib)        |
|        - WGSL Compute Pipelines                                    - Rayon Multicore Parallelism   |
|        - Shared UMA Storage Buffers                                - Exact Bitwise Reproducibility |
|        - Async Fence Mapping                                       - Hardware Independent          |
+----------------------------------------------------------------------------------------------------+
```

### 5.1 Fallback Rules & Guardrails
1. **Explicit Capability Reporting**:
   - `capabilities()` returns `GpuBackendCapabilities` explicitly indicating `CpuFallback` availability.
   - Callers are informed whether hardware acceleration is engaged; CPU fallbacks are never labeled as GPU hardware.
2. **Zero Unhandled Panics**:
   - Out-of-range entity indices, buffer shape mismatches, and invalid ranges return typed `NumericBatchError` envelopes (`EntityOutOfRange`, `BufferShapeMismatch`, `OutOfRangeBin`).
3. **Execution Parity**:
   - `NumericBatchExecutor::new_cpu_fallback()` transparently executes all 26 catalog workloads through verified reference routines with identical mathematical outputs.
