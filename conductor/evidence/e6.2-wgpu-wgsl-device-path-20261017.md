### 3.1 `batch_transit.wgsl` Specification (`K-TRANSIT`)

`batch_transit.wgsl` evaluates batched agent movements across the spatial emergency department layout established in Phase E5. It accepts start coordinates, destination coordinates, and travel velocities, computing Euclidean distances, expected transit durations, and arrival statuses:

```wgsl
// batch_transit.wgsl: Batched spatial transit and waypoint evaluation
struct AgentTransitQuery {
    start_x: f32,
    start_y: f32,
    dest_x: f32,
    dest_y: f32,
    speed: f32,
    arrival_threshold: f32,
    _pad0: f32,
    _pad1: f32,
};

struct AgentTransitResult {
    distance: f32,
    time_to_dest: f32,
    has_arrived: u32,
    _pad: u32,
};

struct TransitUniforms {
    batch_count: u32,
    _pad0: u32,
    _pad1: u32,
    _pad2: u32,
};

@group(0) @binding(0) var<uniform> uniforms: TransitUniforms;
@group(0) @binding(1) var<storage, read> queries: array<AgentTransitQuery>;
@group(0) @binding(2) var<storage, read_write> results: array<AgentTransitResult>;

@compute @workgroup_size(256)
fn main(@builtin(global_invocation_id) global_id: vec3<u32>) {
    let index = global_id.x;
    if (index >= uniforms.batch_count) {
        return;
    }

    let q = queries[index];
    let dx = q.dest_x - q.start_x;
    let dy = q.dest_y - q.start_y;
    let dist = sqrt(dx * dx + dy * dy);

    var travel_time: f32;
    if (q.speed > 0.0) {
        travel_time = dist / q.speed;
    } else {
        travel_time = 1e38; // Effective infinity for stationary entities
    }

    var arrived: u32 = 0u;
    if (dist <= q.arrival_threshold) {
        arrived = 1u;
    }

    results[index].distance = dist;
    results[index].time_to_dest = travel_time;
    results[index].has_arrived = arrived;
    results[index]._pad = 0u;
}
```

### 3.2 `candidate_scoring.wgsl` Specification (`K-CAND`)

`candidate_scoring.wgsl` evaluates calibration parameter sets across empirical observation arrays. Each workgroup evaluates one parameter candidate using shared-memory tree reduction:

```wgsl
// candidate_scoring.wgsl: Multi-candidate calibration evaluation with tree reduction
struct CandidateUniforms {
    observation_count: u32,
    candidate_count: u32,
    metric_kind: u32, // 0 = MSE, 1 = W1 presorted, 2 = KS distance
    _pad: u32,
};

@group(0) @binding(0) var<uniform> uniforms: CandidateUniforms;
@group(0) @binding(1) var<storage, read> reference_obs: array<f32>;
@group(0) @binding(2) var<storage, read> candidate_preds: array<f32>;
@group(0) @binding(3) var<storage, read_write> candidate_scores: array<f32>;

var<workgroup> sdata: array<f32, 256>;

@compute @workgroup_size(256)
fn main(
    @builtin(workgroup_id) group_id: vec3<u32>,
    @builtin(local_invocation_id) local_id: vec3<u32>
) {
    let cand_idx = group_id.x;
    if (cand_idx >= uniforms.candidate_count) {
        return;
    }

    let tid = local_id.x;
    let n = uniforms.observation_count;
    let cand_offset = cand_idx * n;

    // Grid-stride loop accumulation into thread local register
    var acc: f32 = 0.0;
    var i = tid;
    while (i < n) {
        let p = candidate_preds[cand_offset + i];
        let r = reference_obs[i];
        let diff = abs(p - r);

        if (uniforms.metric_kind == 0u) {
            acc = acc + (diff * diff); // MSE
        } else {
            acc = acc + diff;          // Presorted W1
        }
        i = i + 256u;
    }

    sdata[tid] = acc;
    workgroupBarrier();

    // In-workgroup parallel reduction tree
    for (var s: u32 = 128u; s > 0u; s = s >> 1u) {
        if (tid < s) {
            sdata[tid] = sdata[tid] + sdata[tid + s];
        }
        workgroupBarrier();
    }

    // Workgroup leader writes normalized final candidate score
    if (tid == 0u) {
        candidate_scores[cand_idx] = sdata[0] / f32(n);
    }
}
```

### 3.3 Shader Validation, Alignment Rules, and Workgroup Sizing

1. **16-Byte Uniform Buffer Alignment (`std140` / `std430`)**:
   - Uniform buffers in WGSL strictly enforce 16-byte alignment rules (`offset % 16 == 0`).
   - All structs (`AgentTransitQuery`, `AgentTransitResult`, `TransitUniforms`) are padded with explicit trailing `_pad` fields ensuring their byte sizes are multiples of 16 (e.g. `AgentTransitQuery` is exactly 32 bytes; `AgentTransitResult` is exactly 16 bytes).
2. **Workgroup Size 256**:
   - Apple Silicon GPUs execute threads in SIMD-groups of 32 threads. Sizing workgroups to 256 threads ($8 \times 32$) maximizes execution unit occupancy, ensures coalesced 128-bit memory bus transactions, and avoids thread divergency.
3. **Naga Compile-Time Validation**:
   - Shaders are parsed and validated at module construction via `wgpu::ShaderModuleDescriptor`. Type errors, unbound globals, or misaligned buffer accesses fail closed at pipeline initialization rather than during runtime dispatch.

## 4. Non-Negotiable Architectural Invariant: CPU-Owned Queue Arbitration

The core architectural principle of CareOps Sim and Kairos is the **strict separation between discrete causal state transitions and dense continuous numeric acceleration**. Task E6.2 mathematically formalizes and programmatically enforces this boundary.

```
+----------------------------------------------------------------------------------------------------+

+----------------------------------------------------------------------------------------------------+
|                                                                                                    |
|   CPU DOMAIN: Contract Class D0 (Strictly Authoritative & Single-Threaded Deterministic)            |
|   +--------------------------------------------------------------------------------------------+   |
|   |  - Authoritative Clock Advance: tick_ns(t+1) > tick_ns(t)                                  |   |
|   |  - Monotonic Virtual Time & Event Insertion                                                |   |
|   |  - Priority FIFO Event Queue Arbitration (t_event, seq_tiebreaker)                         |   |
|   |  - Bed, Resuscitation Bay, & Staff Capacity Allocation State Machines                     |   |
|   |  - Pseudo-Random Number Generation (Philox-4x32 / PCG-64 Independent Seed Streams)         |   |
|   +--------------------------------------------------------------------------------------------+   |
|                                                 |                                                  |
|                        Numerical Vector Slices  |  Computed Batch Results                          |
|                        (Read-Only Extraction)   |  (Float / Integer Slices)                        |
|                                                 v                                                  |
|   DEVICE DOMAIN: Contract Classes D2 - D4 (Purely Stateless Numerical Transformation)              |
|   +--------------------------------------------------------------------------------------------+   |
|   |  - wgpu / Metal Numerical Accelerator                                                      |   |

|   |  - Parameter Candidate Metric Reduction & Scoring (candidate_scoring.wgsl)                |   |
|   |  - ZERO ACCESS to Event Queue Memory                                                       |   |

|   +--------------------------------------------------------------------------------------------+   |
+----------------------------------------------------------------------------------------------------+
```

### 4.1 Formal Mathematical Invariant Proof

Let the Discrete Event Simulation state at virtual timestamp $\tau \in \mathbb{N}$ be defined as the tuple:
$$\mathcal{S}(\tau) = \left( \tau, \mathcal{Q}, \mathcal{R}, \mathcal{P}, \Omega \right)$$
where:
- $\tau \equiv \mathrm{tick}_{ns}$ is the monotonically advancing virtual clock timestamp in integer nanoseconds.
- $\mathcal{Q} = \{ (t_i, k_i, e_i) \}$ is the prioritized multiset of pending discrete events, ordered lexicographically by timestamp $t_i \ge \tau$ and FIFO insertion sequence key $k_i \in \mathbb{N}$.
- $\mathcal{R}$ is the discrete clinical resource occupancy matrix (beds, nurses, triage officers).
- $\mathcal{P}$ is the persistent patient entity state table.
- $\Omega$ is the deterministic PRNG state stream.

Let $\kappa_{\mathrm{GPU}}: \mathcal{X}_{\mathrm{batch}} \to \mathcal{Y}_{\mathrm{batch}}$ denote any GPU compute shader execution (e.g. `K-TRANSIT` or `K-CAND`).

#### Theorem 1 (Queue & Clock Invariance Theorem):
$$\forall \kappa_{\mathrm{GPU}},\quad \frac{\partial \mathcal{Q}}{\partial \kappa_{\mathrm{GPU}}} = \emptyset, \quad \frac{\partial \tau}{\partial \kappa_{\mathrm{GPU}}} = 0, \quad \frac{\partial \mathcal{R}}{\partial \kappa_{\mathrm{GPU}}} = \emptyset, \quad \frac{\partial \Omega}{\partial \kappa_{\mathrm{GPU}}} = \emptyset$$

*Proof*:
1. By construction of the wgpu pipeline interface, `GpuExecutionPlan` accepts only bounded numerical slices $\mathcal{X}_{\mathrm{batch}} \subset \mathbb{R}^{d \times N}$.
2. The GPU address space possesses zero pointers, bindings, or references to the heap memory containing $\mathcal{Q}$, $\tau$, $\mathcal{R}$, or $\Omega$.
3. When `execute_transit()` or `execute_candidates()` returns, the host simulation loop inspects only the returned vector $\mathcal{Y}_{\mathrm{batch}}$.
4. Event popping ($\min_{(t, k)} \mathcal{Q}$), event insertion ($\mathcal{Q} \cup \{(t_{\mathrm{new}}, k_{\mathrm{new}}, e)\}$), and clock advance ($\tau \leftarrow t_{\mathrm{next}}$) are executed solely by host CPU code in `crates/careops-ed/src/arrivals.rs` and `crates/careops-ed/src/operations.rs`.
5. Therefore, the device kernel cannot mutate discrete event queues, reorder tie-breakers, alter resource allocations, or advance virtual time. $\blacksquare$

### 4.2 Concrete Operational Rules
1. **Clock Monotonicity**: The authoritative clock $\mathrm{tick}_{ns}$ is never advanced by a GPU compute shader or driver timer. Virtual time advance occurs strictly when the CPU event scheduler dequeues the next head event.
2. **Deterministic Tie-Breaking**: When multiple patients arrive or complete triage at the identical nanosecond ($t_a = t_b$), ordering is resolved strictly by the CPU-assigned 64-bit sequence counter $k_a < k_b$.
3. **No In-Kernel RNG Generation**: All stochastic draws (sampling from log-normal service times or Weibull arrival distributions) are performed host-side using seeded PRNG streams. The GPU receives pre-evaluated numerical parameters.

### 5.1 Graceful Zero-Panic Fallback

When a compatible GPU adapter is not detected, `NumericBatchExecutor` automatically initializes `CpuFallbackCompute`:
- **Transparent Execution**: All 26 Report 26 workloads, including `K-TRANSIT` and `K-CAND`, execute seamlessly on CPU.
- **Identical Numerical Contracts**: Floating-point outputs strictly obey Contract Class `D2` ($|\mathrm{err}| \le 10^{-6}$), metric reductions satisfy Contract Class `D3`, and rankings satisfy Contract Class `D4`.
- **Zero Process Crashes**: Unsupported environments do not panic, exit, or fail closed during initialization; they operate with complete functional parity.

### 5.2 Explicit Capability Reporting & Anti-Spoofing Rule

To prevent invalid benchmarking where CPU fallback execution is falsely claimed as hardware acceleration:

```rust
pub struct GpuBackendCapabilities {
    pub is_hardware_accelerated: bool,
    pub backend_name: &'static str,
    pub supports_transit_pipeline: bool,
    pub supports_candidate_scoring: bool,
    pub device_telemetry: Option<GpuDeviceTelemetry>,
}
```

- **Contractual Anti-Spoofing Guarantee**: If `backend_name == "cpu-fallback"`, `is_hardware_accelerated` is unconditionally `false`, and `device_telemetry` records `None` or an explicit `CpuFallback` descriptor.
- Automated tests verify that CPU fallback execution can never be reported under a GPU hardware label.
