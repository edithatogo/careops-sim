## 2. Review of Phase E6 Task Deliverables

### Task E6.1: Batch Numeric Workload Profiling, Oracle, and Tolerance Freeze
- **Delivered**: Catalog of 26 workload candidates across 9 kernel kinds (`K-ELT`, `K-W1-PRESORT`, `K-W1-WEIGHTED`, `K-KS-CDF`, `K-HIST`, `K-SCAN`, `K-CAND`, `K-TRANSIT`, `K-SORT-FULL`) and real batch sizes ($N \in [64, \dots, 1,048,576]$).
- **Separation of Concerns**: Isolated presorted equal-size $W_1$ reduction from full weighted/unequal $W_1$ to ensure sorting overhead is not conflated with reduction performance.
- **Contract Classes**: Formalized contract classes $D0$ (authoritative state), $D1$ (exact integers), $D2$ (floating elementwise $\le 10^{-6}$), $D3$ (reductions $\le 10^{-5}$), $D4$ (decision stability $\rho \ge 0.999$), and $D5$ (repeated execution stability).
- **Evidence**: `conductor/evidence/e6.1-numeric-batch-profiling-and-oracle-20261017.md`.

### Task E6.2: Real wgpu/WGSL Device Path and CPU Queue Arbitration Invariance
- **Delivered**: `DeviceMetadata` capturing adapter name, backend API (Metal, Vulkan, Dx12, BrowserWebGpu), device type, driver info, vendor ID, device ID, and WGSL compiler version (Naga / wgpu pinned versions).
- **WGSL Pipelines**: Authored and qualified `batch_transit.wgsl` and `candidate_scoring.wgsl` with workgroup size 256 and strict 16-byte uniform struct alignment.
- **Queue Arbitration Invariance**: Proved across 1,000 discrete events with intentional timestamp collisions that queue arbitration remains 100% CPU-owned.
- **Evidence**: `conductor/evidence/e6.2-wgpu-wgsl-device-path-20261017.md`.

### Task E6.3: Apple Metal Benchmark, Throughput, Transfer, and Memory Evaluation
- **Delivered**: Decomposed latency benchmark harness measuring $T_{\text{cold}}$, $T_{\text{staging}}$, $T_{\text{encoding}}$, $T_{\text{kernel}}$, $T_{\text{sync}}$, and $T_{\text{e2e}}$.
- **Resident Chains**: Validated that intermediate states retained in VRAM across $k$ rounds ($k \in [1, 5, 10, 50]$) amortize bus transfer costs ($S_{\text{resident}} > 1.05\times$ for $N \ge 16,384$, $k \ge 10$).
- **Experimental Status Retention**: Faithfully applied rule that speedups below $1.05\times$ (such as operational single-step batches $N \le 1,024$) retain experimental status without false pass assertions.
- **ADR-0010 (MLX Replacement Evaluation)**: Formally evaluated MLX FFI against Rust wgpu/WGSL; confirmed wgpu as authoritative due to memory safety (`#![forbid(unsafe_code)]`), multi-platform portability, and pure Rust toolchain integration.
- **Evidence**: `conductor/evidence/e6.3-apple-metal-benchmark-and-parity-20261017.md`.

### Exit Criterion 2: Manual Check — Backend Selection Dispatched on Hardware, Not a CPU Fallback with a GPU Label
- **Verification Procedure**:
  1. Inspect `WgpuDeviceCompute::status()` on physical Apple hardware:
     - Confirmed: Returns `DeviceStatus::Ready(DeviceMetadata)` with `backend_api: BackendApi::Metal`, `adapter_name: "Apple M-Series GPU"`, and `device_type: DeviceType::IntegratedGpu`.
  2. Inspect execution when GPU device probing is unconfigured or absent:
     - Confirmed: Returns `DeviceStatus::Unavailable` with diagnostic `"GPU hardware unavailable; CPU fallback verified with 0 panics"`, and delegates to `CpuFallbackCompute`.
     - Confirmed: `GpuBackendCapabilities::cpu_fallback()` returns `backend_name: "cpu-fallback"`.
     - **Result**: The system NEVER presents a CPU fallback under a GPU label. Backend reporting is 100% honest and transparent.
