## 2. Distributed Coordinator & Worker Daemon Architecture

The distributed simulation runtime is structured around two distinct daemon roles:
1. **Cluster Coordinator Daemon**:
   - Maintains the authoritative node membership registry and routing directory.
   - Initiates periodic GVT consensus epochs (cuts).
   - Coordinates dynamic load balancing and LP migrations.
2. **Worker Daemon**:
   - Manages local LP event queues and state transitions.
   - Routes outbound messages using the cluster routing directory.
   - Maintains per-epoch transmission and receipt counters (`balance = sent - received`).

## 3. Mattern's Distributed GVT Consensus Algorithm

In distributed PDES, messages in transit across the physical network represent uncommitted simulation events that bound the system's global safe time horizon.

### Mathematical Formulation
1. **Epoch Cut Request**: The coordinator broadcasts epoch identifier $E$.
2. **Local Vector Cut**: Each node $i$ captures:
   - Its local simulation clock $T_{i,\text{local}}$.
   - Its message balance $C_i = N_{\text{sent}} - N_{\text{recv}}$ since epoch $E-1$.
   - The minimum timestamp of any message received in transit during epoch $E$: $M_{i,\text{transit}}$.
3. **Consistency Verification**:
   $$\sum_{i \in \text{Nodes}} C_i = 0$$
   If $\sum C_i \ne 0$, messages remain unacknowledged in transit; the coordinator holds the cut open until balance converges to zero.
4. **GVT Calculation**:
   $$\text{GVT}_E = \min\left(\min_i(T_{i,\text{local}}),\ \min_i(M_{i,\text{transit}})\right)$$
5. **Monotonicity Enforcement**: $\text{GVT}_E \ge \text{GVT}_{E-1}$. If an out-of-order clock regression is detected, the coordinator rejects the cut with `GvtCausalityRegressionError`.

## 4. Dynamic LP Worker Migration

To balance CPU or memory utilization across cluster nodes:
1. Coordinator issues migration command: `migrate_lp(LP_RESUS, Node 0, Node 1)`.
2. Node 0 pauses `LP_RESUS` at current safe horizon and emits state digest.
3. Coordinator atomically updates routing directory: `LP_RESUS` $\to$ `Node 1`.
4. Node 1 ingests state digest, allocates clinical capacity (2 resus bays), and resumes event dispatch.
5. All future `RemoteEvent` handoffs targeting `LP_RESUS` are immediately routed to `Node 1`.
