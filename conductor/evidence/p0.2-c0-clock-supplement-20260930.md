deterministic conversion fixture remain open. Reviewer: `gpt-6-luna` subagent
`p02_clock_owner`, 2026-09-30. This supplements, and does not rewrite, the
selected C0 panel's row 90 `defer` recommendation.

The reviewer checked Kairos `SimTime`/`SimDuration` (`u128` logical ticks with
checked arithmetic), its core contract's nanosecond precision mode, the ED
parameter inventory, the calibration timestamp requirements, and the P0.2
interface draft. Kairos does not prescribe a global tick quantum or civil-time
adapter. A versioned CareOps adapter may select one nanosecond per tick without
changing Kairos core semantics.

Recommended row-90 replacement:

> CareOps profile v1 uses decimal seconds for external durations and one
> nanosecond per Kairos tick. Parse fixed decimals exactly and reject negatives,
> non-integral nanoseconds, non-finite spellings and `u128` overflow. Extra
> trailing zeroes are allowed when the scaled value is exact. Convert finite,
> nonnegative sampled durations by deterministic ceiling of an exact rational
> sample or the exact represented value of a versioned sampler output; preserve
> zero. Record sampler/conversion version and rounded-draw count. Relative
> schedules start at logical zero. Timestamped datasets declare one UTC origin,
> preserve source zone/offset, original precision and occurrence-versus-recorded
> lineage, and resolve local DST folds/gaps explicitly before checked conversion.
> Civil-time interpretation stays outside Kairos core.
