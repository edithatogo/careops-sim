# P0.2 E0/C0 interface owner review brief — 2026-09-30

**Status: ready for named owner response; no owner decision is implied.** The
101-row mapping is a proposal and its rows remain `proposed_requires_E0_C0_owner_review`.
This package gives the E0 and C0 owners a bounded review surface and a place to
record their exact responses.

## Review boundary

- **E0 — generic ED model/configuration:** review proposed consumers, stable
  configuration keys, unit-bearing input shape and profile stage/use against the
  generic ED MVP and later hardened v1.
- **C0 — empirical calibration/data interface:** review units and time semantics,
  timestamp origin/precision/timezone, conversion to Kairos integer ticks,
  rounding, measurement/profile applicability, and which inputs are calibration
  targets versus generative inputs.
- Review every row in
  [`p0.2-owner-review-response-template.csv`](../../model-inputs/ed/schema/p0.2-owner-review-response-template.csv).
  For each relevant E0 and C0 disposition use `accept`, `revise`, `defer`, or
  `not_applicable`; `not_applicable` requires a reason. Record the owner's name,
  rationale and date. A revised choice must identify the proposed replacement.
  The two owners must record a joint resolution for cross-cutting disagreements.

## Evidence and closure rule

The proposal covers 101 stable IDs and asserts no empirical numeric values,
distributions, clinical policy, frozen API or approved profile. Existing matrix
validation establishes structural coverage only. P0.2 remains open until named E0
and C0 owners have responded to each applicable choice, conflicts are jointly
resolved, the matrix is updated, the validator and tests pass, and the manual P0.2
walkthrough is recorded. The owner responses must not be inferred from Kairos
ownership, generic project approval, schema validation or this brief.

## Response return

Return the completed CSV plus a short joint disposition naming each owner, the
accepted/revised/deferred choices, rationale, date, and any unresolved item. Any
unresolved or deferred interface needed by the MVP remains a P0.2 blocker; do not
silently freeze it in implementation.
