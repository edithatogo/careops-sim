# P0.2 E0/C0 interface owner review brief — 2026-09-30

**Status: ready for independent agent-panel review; no interface decision is implied.** The
101-row mapping is a proposal and its rows remain `proposed_requires_E0_C0_owner_review`.
In this single-person repository, independent agents review the E0 and C0
interfaces in named roles. The coordinator records the final disposition and
remains accountable for it; matching agent votes alone do not establish acceptance.

## Review boundary

- **E0 — generic ED model/configuration:** review proposed consumers, stable
  configuration keys, unit-bearing input shape and profile stage/use against the
  generic ED MVP and later hardened v1.
- **C0 — empirical calibration/data interface:** review units and time semantics,
  timestamp origin/precision/timezone, conversion to Kairos integer ticks,
  rounding, measurement/profile applicability, and which inputs are calibration
  targets versus generative inputs.
- Review every row in
  [`p0.2-owner-review-response-template.csv`](../../model-inputs/ed/schema/p0.2-owner-review-response-template.csv).
  For each relevant E0 and C0 disposition use `accept`, `revise`, `defer`, or
  `not_applicable`; `not_applicable` requires a reason. Record reviewer role,
  agent/session identity, base commit, rationale, evidence locator and date.
  A revised choice must identify the proposed replacement. The coordinator
  resolves disagreements with a written rationale and leaves unresolved MVP
  interfaces open for escalation.

## Evidence and closure rule

The proposal covers 101 stable IDs and asserts no empirical numeric values,
distributions, clinical policy, frozen API or approved profile. Existing matrix
validation establishes structural coverage only. P0.2 remains open until
independent E0 and C0 role reviews cover each applicable choice, the coordinator
records all six cross-cutting decisions and resolves conflicts, the matrix is
updated, the validator and tests pass, and the manual patient/staff walkthrough
is recorded. The dispositions must not be inferred from Kairos
ownership, generic project approval, schema validation or this brief.
