provisional coordinator disposition and replacement proposals: data rows 1–34,

## Coordinator reconciliation

- Row 35, `ed.durations.disposition`: the reviewer preferred defer to the
  provisional revise because the E0 reviewer deferred a generic disposition
  duration. Keep the provisional **revise** only as an optional, route-specific
  active-work interval whose task owner and decision-ready/work-complete events
  are explicit. A profile without that task omits the key. No generic sampled
  disposition duration is authorized; boarding, bed search, transport and
  physical departure remain separate. The actual route binding is an E0
  implementation gate, so this decision is not yet a frozen matrix row.
- Row 62, `ed.spatialabm.scaledistance`: the reviewer preferred revise to the
  provisional accept because the name can mean drawing scale or graph length.
  Treat the proposed metre value solely as a versioned **graph-edge length**.
  A dimensionless drawing scale, coordinate transform and imported geometry
  require separate fields/contracts. Rename or explicitly qualify the key in
  the next matrix revision before it is accepted.
- Row 68, `ed.spatialabm.travelinterruptions`: retain revise. The optional
  Micro rule needs typed cause, progress, pause and resumption; route time must
  exclude separately generated pause time.

The three reviewers also confirmed the main MVP interface gates: row 36 boarding
is an observed boundary interval and cannot be sampled on top of bed-offer and
transport events; row 37 separates Macro travel from Micro graph travel; row 63
requires named locations and resource/staff bindings in Macro; row 75 separates
external competing admission demand from ED-generated admission requests; row 89
needs an MVP run seed; row 90 removes a global time-unit switch and uses the
scoped ADR-0004 clock contract. These are proposed contracts until incorporated
into the revised matrix and checked by appropriate negative fixtures and the
patient/staff walkthrough.

## Integration evidence and limits

The v3 capacity/location schema and semantic validator are integrated. The
coordinator ran 24 focused capacity tests, validated three synthetic capacity
examples and ran 173 harness tests on commit `2289370`; all passed. The
independent validator review identified two false-acceptance cases which were
fixed before that commit: a resource-requiring task with no eligibility and a
location-scoped staff shortfall masked by staff at another location.

These checks validate proposed static bindings, not a running ED model. Required
tasks with no resource requirements still need profile-level membership checks.
Rust clock conversion, finite admission-boundary behavior, seed replay and the
end-to-end E0 fixture remain unverified. The proposed 101-row CSV retains blank
`resolved_at` fields; no empirical value, distribution or public source is
promoted by this review.
