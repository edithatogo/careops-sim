# P0.2 generic ED input walkthrough

**Status:** coordinator design walkthrough, 2026-09-30. This checks ID coverage
for a synthetic patient and staff task; it does not validate a running model,
clinical parameter values or source distributions. Inputs are the 101-ID
proposal and the independent E0/C0 response candidate at parent `13d335c`.

## One patient

1. An arrival is generated by `ed.demandcasemix.arrivals` under
   `ed.demandcasemix.arrivalmode`, bounded by `ed.experimentcontrols.horizon`
   and a single run seed under `ed.experimentcontrols.seedstreams`. The arrival
   receives a scale-versioned acuity from `ed.demandcasemix.acuitymix`.
2. The patient enters named location and zone IDs under
   `ed.spatialabm.locations`; triage uses `ed.despathways.triage`,
   `ed.despathways.priorities`, staff eligibility and a configured active-work
   duration under `ed.durations.intrinsicwork`. Waiting is generated by the
   queue rather than sampled again as a service duration.
3. Assessment, diagnostics and treatment use `ed.despathways.assessment`,
   `ed.despathways.diagnostics`, and `ed.despathways.treatment`, with staff,
   room, bed and equipment inputs from `ed.resources.*`. Any report review
   delay uses its own event endpoints (`ed.durations.reportreviewdelay`). Macro
   mode may use a declared aggregate transit residual; Micro mode needs the
   optional graph and speed inputs. These modes must not both add the same
   transit interval.
4. A patient who is discharged uses `ed.despathways.discharge`; a patient who
   needs admission uses `ed.despathways.admission` plus the finite inpatient
   offer boundary (`ed.hospitalinterfaces.inpatientbedavailability`). The
   admission decision does not free the ED space. Boarding starts at that
   decision and ends on actual ED departure, subject to the reviewed anchors
   under `ed.durations.boarding`; bed offers, acceptance and transport are
   separate. External competing admission demand, if enabled, is distinct from
   ED patient arrivals under `ed.hospitalinterfaces.admissiondemand`.
5. The vacated ED space is cleaned under `ed.durations.cleaning` and
   `ed.resources.cleaningcapacity` before becoming open/eligible. Throughput,
   length of stay, waiting, occupancy, and unfinished counts need versioned
   event definitions and denominators. `ed.measurementmapping.*` rows are
   currently staged for hardened v1, so E2 must at least define internal metric
   event anchors and denominators without claiming EHR calibration.

## One staff task

1. `ed.resources.staffroles`, `ed.resources.staffcounts`,
   `ed.resources.rosters` and `ed.abmstaffbehavior.zoneskilleligibility`
   establish who is present and eligible at the decision time. A count of
   employed staff is not effective concurrent capacity.
2. `ed.abmstaffbehavior.assignment`, `ed.abmstaffbehavior.taskchoice`, and
   `ed.abmstaffbehavior.urgencyfifo` choose from the eligible queue, with
   one active task per agent unless a separately reviewed concurrency rule
   supports otherwise. Named task/resource/location IDs are needed even in
   Macro mode. Optional Micro route inputs add graph movement and speed.
3. If an urgent task interrupts the current task, `ed.despathways.preemption`
   and `ed.abmstaffbehavior.interruptionresumption` bind to the reviewed Kairos
   Q lifecycle. The model records interruption cause, elapsed/remaining work,
   first subsequent task and eventual resume/abort/restart; it does not infer
   those from an undifferentiated observed gap.

## Gaps exposed by the walkthrough

- The proposed row for `ed.spatialabm.locations` is staged
  `MVP_optional_spatial`, yet named locations/zones and resource/staff bindings
  are needed for the nonvisual Macro MVP. Revise its stage/use so named IDs are
  MVP minimum and coordinates/route geometry remain optional Micro fields.
- `ed.experimentcontrols.seedstreams` is staged `hardened_v1`, but a single
  run seed is required for E2 reproducibility. Move the basic seed to MVP and
  keep named stream allocation under Kairos Track 01.
- The current profile-use text is generic across many rows. Specify required
  versus conditional inputs for each supported fixture. Deferred rows must be
  absent from the profile or block a profile that requires them.
- The clock profile, boarding boundary, staff count basis, and finite offer
  semantics need their revised contracts and negative fixtures before P0.2 can
  be accepted. No empirical values or source distributions were established
  by this walkthrough.
