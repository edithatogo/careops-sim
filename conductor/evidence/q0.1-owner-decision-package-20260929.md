# Q0.1 Kairos owner decision package

**Status:** owner disposition recorded; implementation and release gates remain.
**Scope:** architecture/compatibility gates for the proposed first-class DES Flow runtime.
**Decision evidence:** [ADR-0003](../design/queue/ADR-0003-flow-runtime-contract-proposed.md), [Kairos review gate proposal](../../libs/kairos/conductor/research/careops-flow-api-review-gate-proposal-20260929.md), and [upstream refresh](q0.1-upstream-refresh-20260929.md).

The Q0.1 proposal leaves were locally accepted as design research. The Kairos
owner then directed adoption of the four recommended dispositions and instructed
the coordinator to proceed with the remainder of the track and address blockers.
This is recorded as approval of the directions below, not as approval of concrete
method signatures, implementation, or release. The exact technical clarifications
and separate remaining gates are recorded below.

## Decision areas and selected dispositions

| Decision area | Selected direction | Alternative if that direction changes |
|---|---|---|
| **Track 01 — runtime bounds and cleanup** | Approve a fresh private FlowRuntime with facade-only mutation, cumulative per-runtime limits of `u32::MAX` successful schedule/create/despawn operations, and typed cleanup hooks for Flow-owned component types. State guarantees apply only when hooks and `World::despawn` succeed. Do not claim global core/state overflow safety; no core API change in Q1. | Open a separate Track 01 core/state design and test task for checked counters/generations before queue implementation. |
| **Track 03 — shared DES/ABM behavior boundary** | Approve the shared scheduler/world/registry owned by FlowRuntime in DES, with a separate Flow-specific ABM adapter in `kairo-ecs-abm` depending on DES. Give handlers read-only shared-state queries and a buffered checked-command sink applied at deterministic dispatch boundaries. Preserve existing standalone ABM APIs and `BehaviorSimulation`. | Request a separate `kairo-ecs-flow` crate or other dependency direction; that requires an additional crate/API-root review and revised ADR before fixtures. |
| **Track 25 — API compatibility boundary** | Register exact DES and ABM Rust roots as experimental, because both will gain public Flow symbols; align inventory, versioning policy, compatibility matrix/release note, API review record and validator. Keep concrete symbols and release under hold pending Q0.2/Q0.3 and implementation review. | Name an alternative exact protected root/boundary that satisfies Track 25's required inventory match. No public implementation until this is accepted. |
| **Track 22 with 01/03/04/25 — continuation/checkpoint** | Keep continuation context typed, owned and in-memory for this track. Defer portable serialization/resume to Track 22's coordinated, versioned checkpoint contract. Do not create a second snapshot format. | Bring checkpoint serialization into this track and jointly revise ownership, codec and compatibility contracts before Q0.2. |
