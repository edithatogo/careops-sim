## Review and verification

The fixture contains five synthetic cases and nine operation snapshots:

1. A release at the exclusive deadline expires the queued claim before grant.
2. A timeout token at the deadline yields the same result; later release cannot
   grant the timed-out request.
3. Work completing at T is completed before a same-tick preempting admission;
   the incoming claim uses the freed capacity without interrupting the completed
   work.
4. Shrinking capacity below two active allocations is rejected atomically.
5. From idle capacity 1, capacity is reduced to 0, claim C is submitted and
   queued at zero, then capacity grows to 1 and grants C. The earlier attempt's
   capacity-2/idle/queued initial state was unreachable under the drain rule; it
   was preserved as rejected review evidence and replaced before acceptance.

An independent read-only review replayed all five cases and all nine snapshots.
The coordinator also asserted the boundary outcomes and staged the fixture before
running `git diff --cached --check`, which covers the new file. Snapshot encoding
is fixture-local: active/queued/terminal are object arrays; terminal records and
lifecycle ID arrays are ordered and cumulative within a case; `accepted` is a
per-operation boolean. This does not freeze a shared queue fixture schema.
