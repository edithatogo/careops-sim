## Decision memo

The principal conclusion is to separate three problems that are sometimes grouped under “parallel simulation” but have very different semantic costs.

**Independent replications should be the first multicore and distributed target.** Each replication can retain the existing serial event semantics, authoritative state and clock. Parallelism exists between simulations rather than inside one simulation. Provided the replication identifier deterministically selects its random stream, thread/process scheduling need not affect a replication's event history. This gives the cleanest route to using multiple cores and later multiple machines without introducing inter-LP causal synchronisation. Counter-based random-number construction is particularly well suited to making random draws functions of stable semantic addresses rather than execution order. [`SRC-RNG-SALMON2011`, `SRC-RNG-LECUYER2002`]

**Within-run conservative PDES should be an experimental, gated phase rather than the default Kairos scheduler.** Conservative PDES can preserve causality by allowing a logical process to execute only events known to be safe from an earlier incoming message; the classic Chandy–Misra work develops this family of distributed simulation protocols, including communication of lower bounds/null information to avoid waiting indefinitely for messages that cannot arrive. The useful amount of parallelism is controlled by model topology, communication, workload balance and especially usable lookahead. [`SRC-PDES-CM1979`, `SRC-PDES-CM1981`, `SRC-PDES-FUJIMOTO1990`]

For Kairos, **positive lookahead is presently unknown**. It must not be invented from ED waiting time or length-of-stay statistics. A valid PDES lookahead is a guaranteed model-semantic lower bound on how soon one partition can causally affect another, not an empirical average duration. If any permissible cross-partition transition can generate a same-simulation-time event, the relevant time lookahead may be zero. Until every cross-partition event path is analysed, a conservative implementation should therefore support and test zero lookahead explicitly rather than assuming a useful positive bound. [`SRC-PDES-CM1979`, `SRC-PDES-FUJIMOTO1990`]

**Cross-node within-run PDES should be deferred behind shared-memory and same-host process experiments.** Network execution adds serialization, buffering, retry, stale-worker and recovery semantics to synchronization costs already present in parallel DES. Fujimoto's analysis gives no basis to infer speedup solely from available concurrency; real measurements are required. [`SRC-PDES-FUJIMOTO1990`]

**Checkpointing should initially be coordinated at an established simulation-safe frontier.** Chandy and Lamport show how a consistent global state can be captured in a genuinely asynchronous distributed computation, including relevant channel state. That machinery is valuable evidence, but it is unnecessary complexity for the first implementation if Kairos can deliberately stop all LPs at a known safe frontier, drain/account for messages and write one coordinated checkpoint. An asynchronous distributed snapshot should remain a later option rather than being imported into the first PDES prototype. [`SRC-SNAPSHOT-CL1985`]

The recommended sequence is therefore:

> **serial reference → parallel independent replications in threads → independent processes → independent nodes → experimental same-process conservative LPs → same-host multiprocess PDES → cross-node PDES only if benchmarks justify it.**

This is a **policy recommendation**, not a claim of existing capability.

## Determinism, partitioning and recovery contract

The crucial distinction is between causality and deterministic identity. Conservative PDES can guarantee that an event is not processed before a causally earlier event while still allowing events with equal simulation timestamps, or causally independent events, to be executed in a different wall-clock order. That distinction matters because an existing Kairos serial tie-break contract may be stronger than ordinary timestamp causality. [`SRC-PDES-CM1979`, `SRC-PDES-CM1981`, `SRC-PDES-FUJIMOTO1990`]

I recommend three explicit equivalence classes:

**Trace identity — `EQ_TRACE`.** The canonical sequence of committed `(simulation_time, deterministic_tie_key, event_id, mutation_digest)` tuples is identical to the serial reference. This is the strongest contract and should be the initial correctness target for deterministic unit/fixture tests.

**State identity — `EQ_STATE`.** Internal execution order may differ, but a canonical state digest at a specified frontier—preferably every completed timestamp during early validation, and always at termination—is identical. This is acceptable only where the reordered operations are proven independent or commutative under the model contract. It must not be treated as automatically equivalent to trace identity.

**Statistical equivalence — `EQ_STAT`.** Repeated runs agree only in predefined distributions or aggregate statistics. This can be a useful validation target for intentionally nondeterministic or numerically approximate backends, but it is too weak to establish Kairos's deterministic event contract. A race or causality defect can disappear inside an aggregate distribution. This is therefore not sufficient acceptance evidence for the proposed conservative CPU scheduler. [`SRC-PDES-FUJIMOTO1990`, `SRC-RNG-SALMON2011`]

**Ownership.** Every mutable simulation object should have exactly one LP owner at any instant: agents, queue state, resource capacity and resource-specific work state included. Cross-LP code should send timestamped messages rather than retaining direct mutable references into another LP. Queue and resource state should be co-located when practical. Given the project-stated current restriction of one resource/capacity unit per work item and deferral of atomic resource bundles, the first PDES experiment need not solve distributed multi-resource atomic acquisition; introducing it as part of PDES would enlarge two hard problems simultaneously. [`SRC-PROJ-001`; ownership scheme is `policy`]

A proposed cross-LP envelope is:

```text
run_id
model_revision
partition_map_revision
sender_lp
sender_incarnation
sender_sequence
recipient_lp
recipient_entity_or_resource
simulation_time
event_phase_or_priority
deterministic_tie_key
event_id
payload_schema
payload
payload_digest
```

`event_id` must be stable across retry. `sender_incarnation` distinguishes packets emitted by a worker before and after recovery. `sender_sequence` allows gap/duplicate diagnostics. `partition_map_revision` prevents messages generated under an obsolete ownership map from silently mutating new owners. These are proposed protocol fields, not fields observed in current Kairos.

**Lookahead.** For every directed LP boundary \(i \rightarrow j\), the scheduler needs a certified lower bound \(L_{ij}\) such that state at LP \(i\) committed through time \(t\) cannot cause an event for \(j\) earlier than \(t+L_{ij}\). A measured mean, percentile or fitted ED delay is not such a guarantee. Static lookahead is the simplest first contract; state-dependent lookahead should be accepted only when the lower-bound calculation itself is deterministic and model-validated. [`SRC-PDES-CM1979`, `SRC-PDES-CM1981`]

There is an additional Kairos-specific issue: **a positive timestamp lookahead does not by itself reproduce the serial order of equal-time events**. If `EQ_TRACE` includes a serial insertion/tie-break order, safe advancement must account for the complete ordering key or use a deterministic same-timestamp closure/barrier. Otherwise conservative timestamp correctness can coexist with a different trace. This is why trace identity should be tested independently of ordinary PDES causality.

**Deadlock and progress.** Null/lower-bound messages can allow conservative LPs to prove that no earlier message will arrive, which is the classic way of overcoming deadlock caused by every LP waiting for another's next real event. [`SRC-PDES-CM1979`, `SRC-PDES-CM1981`] A progress watchdog should report an inability to advance but must not “solve” it by breaking the safe-time rule. With zero usable lookahead, the approved behaviour should be a deterministic barrier/closure algorithm or serial fallback, not speculative execution masquerading as conservative PDES.

**Random streams.** A mutable thread-local PRNG whose draw position depends on which worker happens to execute first is incompatible with scheduling-independent trace reproducibility. Counter-based generators instead make a random result a deterministic function of a key and counter, eliminating dependence on mutable sequential consumption. Salmon et al. introduced this construction for parallel random-number generation; L'Ecuyer's long streams and substreams provide another established mechanism for separating simulation streams. [`SRC-RNG-SALMON2011`, `SRC-RNG-LECUYER2002`]

For the proposed Kairos parallel contract, a random draw should be addressed by stable semantic coordinates such as:

```text
(master_seed,
 replication_id,
 entity_or_component_id,
 causal_event_id,
 random_purpose_id,
 draw_index)
```

That exact tuple is a **policy proposal**, not something specified by the cited papers. `random_purpose_id` is important: adding an unrelated random draw to one part of a handler should not silently shift all subsequent draws associated with other purposes.

**Checkpoint/resume.** A coordinated checkpoint should include at least the model and executable revision, schema versions, simulation frontier, partition map, all owned mutable state, each LP's ordered pending event set, sender sequence counters, receiver deduplication state, LP incarnation data, master seed/RNG addressing schema and integrity hashes. All inter-LP traffic must either be accounted for in the snapshot or excluded by a drain/barrier protocol. This is the coordinated analogue of the consistent-state requirement formalised by Chandy–Lamport. [`SRC-SNAPSHOT-CL1985`]

**Duplicate/retry semantics.** Network “exactly once” should not be assumed. A safer application-level contract is stable message identity plus deduplication, so that retransmission can be permitted while the event's state transition is applied once. Deduplication state must itself survive a checkpoint; otherwise replay after recovery can duplicate effects. A recovered LP should take a new incarnation number and reject delayed packets from an obsolete incarnation. This is a proposed failure/recovery contract.

## Evaluation and failure programme

Performance testing should first answer **whether** there is useful parallelism, not attempt to demonstrate a predetermined speedup. Fujimoto's analysis identifies synchronization, communication, partitioning and load balance as central determinants of PDES efficiency. [`SRC-PDES-FUJIMOTO1990`]

For every configuration, record at least wall-clock elapsed time, committed events/s, total candidate/processed events, CPU time, peak resident memory, worker utilisation, cross-partition message count and bytes, null/lower-bound message count, time blocked waiting for safe advancement, maximum and distribution of LP skew, checkpoint bytes/time, restart time, duplicate/retry count, and the applicable `EQ_TRACE`/`EQ_STATE` result. [`SRC-PDES-FUJIMOTO1990`; metric set otherwise `policy`]

The tests should progress through **real threads, then processes, then physical nodes**:

1. A single-thread reference establishes trace and final-state digests.
2. Independent replications run at fixed replication IDs under varying real thread counts.
3. Independent replications run as separately launched OS processes.
4. The same replications are distributed over at least two physical hosts.
5. A synthetic partitionable model tests conservative LPs with actual OS threads.
6. The same fixture moves to multiple localhost processes.
7. Cross-node within-run execution is attempted only after the preceding fixture retains its equivalence contract and exposes enough useful lookahead to justify the experiment.

The PDES synthetic workload should sweep the two variables most likely to determine the outcome: **cross-partition interaction rate** and **certified lookahead**, including an explicit zero-lookahead case. The fixtures below use logical ticks rather than clinical time; all numeric values are `synthetic`.

Failure testing is as important as throughput:

- zero-lookahead and same-timestamp cyclic traffic must not permit unsafe advancement;
- message duplication must cause one committed effect;
- reordering and delay must not alter the applicable deterministic result;
- old-incarnation traffic after restart must be rejected;
- interruption immediately before and after checkpoint publication must recover to the same reference result;
- a corrupt/truncated checkpoint must fail validation rather than partially load;
- node/worker loss must stop advancement beyond the provable safe frontier;
- deliberately skewed partitions should expose declining utilisation rather than being hidden by aggregate events/s;
- repeated thread-scheduling perturbations must not change counter-addressed random values or the required deterministic digest. [`SRC-PDES-CM1979`, `SRC-SNAPSHOT-CL1985`, `SRC-RNG-SALMON2011`]

These tests deliberately avoid a throughput acceptance threshold such as “2× faster”. A backend that is correct but slower is a valid experimental result and evidence against enabling that execution mode for the tested workload.

```markdown
# Decision memo: Kairos deterministic multicore / PDES / distributed execution

Research date: 2026-09-27 Australia/Brisbane
Inspected public Kairos head: fae901558f07b7b717a676adbafbe2cdc78dea1c
Immediate parent: f26633f30bffc5c0e82717461d90bd13f8c58dc6

Private project attachments available: no

## Decision

1. Preserve the current serial authoritative-state/clock semantics as the reference oracle.
2. Implement/evaluate independent replication parallelism before altering within-run scheduling.
3. Give each replication a deterministic stream namespace independent of worker/thread placement.
4. Define trace identity, state identity and statistical equivalence as distinct acceptance contracts.
5. Do not enable conservative within-run PDES until mutable ownership and cross-LP event envelopes are explicit.
6. Treat positive lookahead as unknown until proven from model semantics; zero lookahead is a required test.
7. Start within-run work with real shared-memory threads and synthetic partitionable fixtures.
8. Use coordinated safe-frontier checkpoints before considering asynchronous distributed snapshots.
9. Make stable event IDs, deduplication, worker incarnation and sender sequence part of the distributed protocol before selecting transport.
10. Defer cross-node within-run PDES until thread and localhost-process measurements show useful concurrency after synchronization costs.
11. Do not infer or promise speedup from theoretical concurrency.
12. Do not change queue/resource semantics or introduce cross-owner atomic bundles as part of this work.
13. Do not approve a third-party runtime/package merely because it is its latest release; current release, MSRV/toolchain, licence, platform and Kairos compatibility require a separate primary-source check.

## Equivalence policy

EQ_TRACE:
Canonical committed event trace is identical to the serial reference.

EQ_STATE:
Canonical state at agreed simulation frontiers is identical, while internal ordering may differ only under an explicitly reviewed independence/commutativity rule.

EQ_STAT:
Only predefined ensemble statistics agree. This is not sufficient to validate deterministic conservative PDES.

Initial within-run PDES acceptance target: EQ_TRACE on focused fixtures.

## Go/no-go criterion

A PDES backend is not promoted merely because it is correct.
Promotion requires both:
- required deterministic/failure semantics; and
- representative benchmark evidence that the additional complexity has a justified operational benefit.

A slower but correct experiment is a legitimate no-go result.
```

## Conflicts, unresolved questions and prioritised evidence acquisition

The largest conflict is between **ordinary conservative causality** and a potentially stronger Kairos **serial event-order identity** contract. Classic conservative PDES establishes when an event is causally safe; it does not automatically reproduce an arbitrary serial insertion order among equal-time independent events. If Kairos's externally visible reproducibility promise includes that exact ordering, within-run PDES either needs a deterministic global ordering/commit mechanism, timestamp barriers with a specified same-time closure, or a formally reviewed relaxation from `EQ_TRACE` to `EQ_STATE` for independent/commutative operations. That semantic choice should precede implementation. [`SRC-PDES-CM1979`, `SRC-PDES-CM1981`, `SRC-PDES-FUJIMOTO1990`]

A second unresolved issue is **actual lookahead in the generic ED graph**. Nothing in the evidence inspected establishes a positive guaranteed lower bound between partition effects. Waiting times, length of stay, fitted treatment durations, means or quantiles cannot substitute for a causal lower bound. The highest-priority model-specific evidence task is therefore to enumerate every event type able to cross a prospective LP boundary and calculate its minimum permitted timestamp advance from model semantics. Any path permitting zero advance forces zero lookahead for that boundary unless ownership/partitioning is changed.

A third gap is the missing private architecture material. `module-readiness.md`, `execution-model.md`, `agent-engineering.md`, the recorded pinned snapshot and the generic-ED development plans should be reconciled against `fae901…` before the proposed envelope, RNG schema or checkpoint format becomes an architectural decision. In particular, existing Kairos event-key, seed and serialization contracts should be reused rather than duplicated if they already provide the necessary identities.

A fourth gap is **upstream package currency and compatibility**. No current Rayon/MPI/Rust/wgpu release is approved by this research. Before introducing any new runtime, the next dependency-specific review should record the exact current release/tag/commit from its original repository, publication date, MSRV/toolchain requirements, supported targets, licence, unsafe-code implications where relevant, determinism caveats and known open issues, then compare those requirements with Kairos's exact `Cargo.lock` and CI platforms. “Latest” should remain a candidate rather than an upgrade instruction.

The evidence-acquisition priority is therefore:

**First:** recover and inspect the pinned project snapshot and missing architecture documents, and diff that snapshot against `fae901558f07b7b717a676adbafbe2cdc78dea1c`.

**Second:** build a serial trace oracle with canonical event/state digests and document the exact tie-breaking contract. Without this, PDES determinism cannot be stated precisely.

**Third:** inventory current random-number use and define stable semantic draw identities before adding thread-level execution. The counter-based approach is well supported for parallel generation, but the exact algorithm and Rust implementation still require compatibility and golden-vector review. [`SRC-RNG-SALMON2011`, `SRC-RNG-LECUYER2002`]

**Fourth:** benchmark independent replications on actual threads, processes and at least two real machines. This provides useful multicore/distributed capacity while preserving within-run semantics and creates the process orchestration, provenance and failure infrastructure needed later.

**Fifth:** derive a boundary-by-boundary lookahead certificate and ownership graph from the generic ED model. Unknown bounds remain unknown; zero is a legitimate and important result.

**Sixth:** implement only the synthetic conservative-PDES harness, including the zero-lookahead, same-time-cycle, ownership, duplicate, checkpoint and RNG fixtures, before attempting a production ED partition. Conservative synchronization has substantial model-dependent overhead, so advancement to a real ED backend should be evidence-driven rather than assumed from theoretical parallelism. [`SRC-PDES-CM1979`, `SRC-PDES-CM1981`, `SRC-PDES-FUJIMOTO1990`]

**Seventh:** attempt cross-node within-run PDES only after shared-memory and localhost-process experiments establish both the required deterministic semantics and enough exploitable concurrency to justify adding network recovery and checkpoint complexity. A negative scaling result at any earlier stage is a useful conclusion, not a failed research programme. [`SRC-PDES-FUJIMOTO1990`]

The resulting architecture keeps independent replication as the low-risk path to immediate multicore/distributed throughput; treats conservative PDES as a separately evidenced optimisation; makes ownership, lookahead, retries, random draws and checkpoints explicit parts of the deterministic contract; and leaves the existing Kairos architecture unchanged unless the proposed fixtures demonstrate a concrete reason for a reviewed change.
